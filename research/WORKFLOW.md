# 研究归档与开发交接流程

## 目的

保证社会历史研究能够长期积累、检索、反驳、修订，并真正服务于 CoopCraft 的 Fabric 1.21.1 开发。避免“每次聊天产生一个互不相联的长文”与“研究结论被当成已通过测试的游戏功能”。

## 文档身份

- `research/`：理论材料、机制假设、玩家体验原型、学术证据和待验证设计。
- `docs/civilization-design.md`：工程主线与当前开发状态；不得因研究稿自动覆盖。
- Issue：下一步问题、争议、设计决策与实验追踪。
- PR：经整理的文档版本、更新记录和可审查的开发变更。
- 代码与测试：最终确认实际实现情况的依据，不由研究文字替代。

## 研究准入：每次新增话题回答5个问题

1. 属于哪个研究单元 S0–S7（可跨单元）和维度 D01–D12？
2. 对应哪条因果链或玩家可玩场景？
3. 复用现有哪个底层对象、API、模拟实验或 GameTest？
4. 期望产物是什么（证据表、阶段卡、算法伪代码、实验对照、交互原型）？
5. 如果暂不研究，会否阻碍当前原始社会核心闭环？若不会，放入待研究 Issue。

## 统一12个维度

D01历史与生态；D02生产力与技术；D03劳动组织；D04财产权；D05分配与流通；D06人口再生产；D07社会分化；D08治理；D09文化与知识；D10物质生活与空间；D11矛盾与变迁；D12玩家体验及测试。完整定义见[跨时代总纲](framework/cross-era-master-v0.1.md)。

## GitHub流程

1. 研究前先搜索 `research/`、`docs/` 和现有 Issue/PR。
2. 如果只是问题或灵感：创建或更新对应研究 Issue，标识 `[远期创意]` 或 `[研究/Sx]`，不得默认为开发任务。
3. 研究形成可复用结论后，在独立分支更新相关文档，创建 PR。PR 描述需解释依据、变化、风险、当前代码影响和是否需要测试。
4. 需改动实际功能时另开开发 PR，引用研究文档与验收实验，不将文档 PR 与大型代码重构混在一起。
5. Review 后合并；旧结论保留链接、变更说明及被取代版本。
6. 每个阶段达成 L2 标准后冻结该版，未完成问题继续归档，不阻塞下一研究单元。

## 研究证据分层

- **[证据]** 出土材料、原始史料或方法透明的研究结论（仍有样本和解释范围）。
- **[解释]** 历史唯物主义、考古学、人类学和制度理论的分析或争论。
- **[假设]** 数值系数、NPC规则、行为模型及游戏化简化。
- **[验收]** JUnit、Fabric GameTest、实际游戏观察和长时随机种子对照。

## 玩家体验与工程质量底线

- 至少一个不依赖玩家的 NPC 自治闭环。
- 玩家行动应改变真实物资、时间、社会记忆或权利，而不是纯 UI 数值。
- 所有物资转移符合单一权威库存与守恒；已存在完整事件溯源的，继续沿用。
- 情境信息不能在未传播时全知同步给所有居民。
- 远处聚落不能无边界实体寻路或无限抢占主线程。
- 实现状态依赖当前仓库最新代码及测试，不沿用历史文档的“已完成”陈述。

## 后续内容更新

聊天里每次正式研究结束，至少提出：**研究ID、对现有知识的增量、关键争论、玩家体验、具体实现边界、未决实验**。需要归档时可更新一个已经存在的专题文档及同一追踪 Issue；不强制每次都新建 Issue。
