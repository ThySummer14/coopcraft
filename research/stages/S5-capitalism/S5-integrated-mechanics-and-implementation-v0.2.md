# S5｜资本主义生产方式：机制研究与工程实现规格 v0.2

> 研究编号：RES-S5-CORE-001；日期：2026-11-05；范围：D01–D12。
> 状态：**L2 设计候选，待模型实验与代码评审**；不是“Fabric 已实现”，也不是要求立即替换 S0 开发。
> 适配：CoopCraft / Minecraft Java 1.21.1 / Fabric；代码核对基线 main `17296af707a08a334a94c4cb75b59472ec2dca5b`。
> 关联：研究文库 PR #24、S5 玩法 Issue #26、[长期创意 v0.1](shop-to-capital-circuit-v0.1.md)、[阶段卡](stage-card.md)。
> 核心决定：**复用跨时代物资与劳动基础，新增产权/货币/契约的通用语义；资本主义仅是其中一种占主导地位的关系组合。**

## 0. 必须先定下的 12 项结论

1. `SettlementStage` 仍表示技术/聚落条件，不增加 `CAPITALISM` 枚举；社会形态是独立、可并存、可逆的统计画像。
2. 店铺≠资本主义；雇佣劳动单独存在也不足以判定主导制度。关键是生产资料控制、工资依赖、商品生产、利润分配及再投资的长期组合。
3. `Asset` 的财产权不等同于箱子里的物资持有者；法律所有、使用、经营、收益、转让等权利必须可分开。
4. 现金、债权、库存、已生产数量、已出售数量和经营盈余分别记账；未售商品绝不能按标价变成现金。
5. 货币是**带发行来源的记账单位**；不允许因 NPC 点击“购买”平空生成余额。全部资金流以整数最小单位进行守恒校验。
6. 原材料、成品仍使用唯一 `ResourceBatch` / Minecraft 真实物品适配路线，不建立企业专用的第二套“虚拟库存”。
7. 工人的实际劳动必须占用可用工时，先保证工资支付能力；离职、拒绝、失业、协商是正常状态，不是惩罚性剧情。
8. 价格和需求必须有实际买家及有限预算，不能无限使用“世界市场自动收购”消化产出。
9. 不强行制造经济危机；亏损、库存积压、违约、企业退出等由订单、资源和融资条件内生触发，允许恢复。
10. 私人雇工、家庭自营、合作社、公营企业共享生产和销售管线，但**谁决定生产、谁取得盈余**实际不同。
11. 马克思 `c+v+s` 是明确标注前提的理论分析，不直接由会计利润反推“剩余价值”；也不把该视角伪装成唯一学术定义。
12. 本阶段开发应分片推进：**经济账本基础 → 小规模工作坊闭环 → 工资/退出 → 价格与资本积累 → 信贷、制度与危机**。

## 1. 历史研究与争议的工程约束 [D01]

- **[证据/概述]** IMF 对资本主义概述包括私人生产性资产、雇佣劳动、市场定价及利润动机（Jahan & Mahmud, 2018，https://www.imf.org/en/publications/fandd/issues/series/back-to-basics/capitalism）；这些是理想型特征，现实存在国家企业、家庭自营与混合经济。
- **[证据/研究]** 工业化改变了长期生产率和经济增长走势（Bank of England, https://www.bankofengland.co.uk/explainers/how-has-growth-changed-over-time）；但工业化的技术轴不与资本主义生产关系轴一一对应。
- **[证据/争论]** 英国工业革命早期融资究竟多依赖内部积累、亲友借贷与银行，经济史尚有争论；不得设置“只有银行贷款才能工业化”式硬门槛（Hodgson 2021，https://www.cambridge.org/core/journals/journal-of-institutional-economics/article/financial-institutions-and-the-british-industrial-revolution-did-financial-underdevelopment-hold-back-growth/422EF61BFB7D0E952845F488FA13E350）。
- **[证据]** 历史劳动时间变化受制度、工资和生产率等多重因素影响，不适用“所有资本主义都必然加班到固定时长”的单向规则（ILO, 2018，https://www.ilo.org/publications/working-time-and-future-work）。
- **[解释]** 商品化、土地权利变化、农村家庭劳动、城市工厂、殖民扩张、强迫劳动和全球贸易曾以不同方式交织；资本主义起源不是全世界共同经历的单一“圈地→工厂”序列。未来专题可研究暴力与不平等，但不可把历史压迫设计成无成本效率奖励。
- **[游戏假设]** 系统用若干可观察关系而非历史年份、蒸汽机数量或职业名称判定形态。所有阈值是调参，不宣称历史普遍规律。

- `SettlementStages.java` 以人口、住房、食物及工位等条件演进 `PRIMITIVE/AGRICULTURAL/TOWN`；此处**技术等级与社会组织分离**。

EconomicActor(actorId, actorKind: PERSON|HOUSEHOLD|ENTERPRISE|COOPERATIVE|PUBLIC_BODY)

MoneyAccount(accountId, actorId, currencyId, balanceMinorUnits)

TradeExecution(executionId, buyOrderId, sellOrderId, batchIds, qty, unitPrice, settlementEventId)

**禁止将所有权和持有者混成同一字段**：例如合作社成员可能共同拥有设备、轮班使用，企业经营者管理，但设备所在地仓库只是保管方。若后期继承或国有化，要转移的是权利事件，不必销毁物品再制造。

对 `StorageOwner` 的扩展建议采用显式命名空间和兼容迁移（如 `ENTERPRISE`，但不能直接让旧 NBT `valueOf` 因未知值崩溃）；具体类型由开发 Agent 对当前保存加载代码评估。工厂商品需要关联 Minecraft 真实物品、批次、坐标及保管地点；未加载区块不执行远程实体取物。

### 3.2 不可违反的不变量

- **物资守恒**：前后商品数量差 = 有来源的生产 - 有来源的消费/损耗 ± 有来源的输入输出。生产配方明确消耗原料、工时、设备寿命；不得“企业加余额就出物品”。
- **钱款守恒**：同币种无发行/注销事件时，所有账户金额之和恒定。玩家/NPC 购买要真正减少买家余额。贷款只形成债权债务或显式放款转移，不默默创造无来源的现金。
- **权利可追索**：资产使用/出售/转让先校验权利束，不能通过把箱子搬走绕过所有者；物品与资产登记关联要防重复认领。
- **劳动不可重叠**：工作、采集、照料、迁移、休息等任务共享时间预算；同一村民同一时段最多一个主要劳动预留。
- **交易与工资原子性**：一笔交易要么同时完成商品转移和付款，要么全部失败；工资支付前冻结可用款，付款失败不得把工时记成已支付。
- **重放幂等**：每个订单成交、生产班次、结算采用全局唯一业务操作 ID；存档/重启/重复 tick 不得重复转移或发钱。
- **不可全知**：居民仅根据价格板、实际可达订单、社交传播、职业经历等已知信息决策。
- **没有离线实体劳动**：未加载区域只可计算不涉及实体操作的受控摘要，不得暗中消耗不在权威库存的真实方块或生成产品。

### 3.3 首期结算顺序

```text
每天/固定市场批次开始
  1. 读取已加载地区、已登记资产/企业、可达买卖报价快照
  2. 形成招工意愿/求职申请；验证工资储备和工时，不强行雇用
  3. 执行已登记的真实 NPC 工作/机器加工并写批次事件
  4. 对完成的工作做工资支付，记录实付/欠付状态（不得无钱成功）
  5. 商品真实上架，按有限预算及可达性撮合订单
  6. 在一次权威事务中提交物品与资金流，失败回滚/拒绝
  7. 更新企业期间账簿、家庭消费预算和可读事件
  8. 企业再投资/减产/停业意愿；政策/契约影响下一结算期
  9. 由事件派生社会形态观察量，定期缓存；批次持久化
```

具体代码按交易状态机设计：`PROPOSED → RESERVED → COMMITTED` 或 `CANCELLED`；预留有到期释放规则，避免死锁和玩家抢走材料。对于目前缺乏跨账本事务机制的工程，P0 **先做纯 Java 模型原型**，不在 Fabric 层伪造多步骤原子性。

## 4. 雇佣劳动、劳动关系与人类行为 [D03、D06、D07]

### 4.1 合同和工时

最小合同字段：雇主、工人、约定班次、工资（整数货币单位）、工作类型、起止日、结算策略、是否可退出。合同是**劳动协议，不是人员所有权**；禁止用原始社会的成员归属替代雇佣契约。

- `offer`：企业公开岗位；岗位数量由当前订单、产能、现金储备决定。
- `accept`：工人比较预期净工资、食物价格、健康、通勤、替代岗位与家庭照料需求；玩家亦可主动申请。
- `reserve`：确认个人本时段可用工时，冻结工资预算，工厂可用。
- `complete`：实际完成劳动才记录产出，发放工资并记录工时。若服务端中断，恢复时先查操作 ID。
- `leave`：班次/合同到期或约定退出；优先允许拒绝续约。法律、惩罚和组织关系若出现，明确标注特定制度约束而非个人“天生不愿工作”。

可调行为函数（**游戏假设**，非历史定律）：

```text
workerUtility = expectedRealWage - commuteCost - healthRiskCost
              - familyCareOpportunityCost + skillGain + workplacePreference
realWage = offeredNominalWage / max(localNecessitiesPriceIndex, epsilon)
```

若无可行工作，可能转为自营、互助、其他工作或暂时失业。不得因 NPC 没工作就给出强制死亡概率，也不得凭空发工资。

### 4.2 阶级不是职业枚举

以时间窗计算个人的：生产性资产净权益、生产决策控制权、工资收入占比、资产收益占比、债务负担、是否聘用他人、对雇主依赖度。农民兼雇工、店主兼雇员、工人兼持股份、合作社工人均允许。UI 显示可解释的多标签而非“老板/工人”锁定阶级。

### 4.3 不直接把政治态度映射成阶级

劳资分歧来自可观察利益和经历：工资购买力下降、工时、风险、拖欠、失业、规则公平性、互助网络。罢工或协商需先有信息共享、动员与成本，居民不因工资略低于平均值自动全体罢工，也不假设阶级必然导致统一政治观点。

## 5. 市场、利润和资本循环 [D05、D11]

### 5.1 真实订单而非「卖出即收钱」

P0 使用小区域、限价订单：买方有实际货币余额和消费理由；卖方有真实商品批次。先冻结买方余额与卖方批次数量；成交价在双方接受范围内；无买家则库存保留，企业承担现金流风险。首版可先用固定报价，**不必为模拟市场价格而实现全球拍卖系统**。

P1 可测试透明的报价更新：以过去数次真实成交价为锚，结合“未成交买单/卖单及真实库存”作有界调价；单期变化上限建议作为配置例如 ±10%，只是防数值振荡的平衡参数。不能没有交易却从全世界主观估值中制造财富。

### 5.2 三个不能混用的财务量

- **现金流** = 真实收款 - 真实付款；可以为正而没有利润（例如借款）。
- **期间会计利润** = 已实现收入 - 本期应计成本（含已售产品成本、工资、租金、维护、折旧、利息等，成本归集规则要固定）。
- **理论剩余价值分析** 需单列劳动价值、必要劳动/剩余劳动等假设，不能直接设为会计利润；初版不输出未经定义的 `surplusValue` 字段。

**资本循环**：`M → C (生产资料 + 劳动力) → P → C' → M'`。某期 `M'` 不一定大于 `M`，也可能因未售存货、亏损而中断。所有循环阶段必须可中途停止、延期、破产或转让。

### 5.3 一个数值完全闭合的木材作坊实例（演示种子）

- 初始企业：现金 100 单位、无其他流动存货；一套已有工位仅作为本例前提，不计新购设备。
- 向真实供应者购入 10 原木 × 2 = **付 20**。
- 两个已完成工作班次共付工资 **20**；维修/其他当期费用付 **10**，各有真实收款方。
- 真实消耗 10 原木和合法工时，产出 40 木板。
- 真实买家购买 30 木板 × 2 = **收 60**；剩余 10 木板仍在库存。
- **期末现金** = 100 − 20 − 20 − 10 + 60 = **110**。
- 若本例采用“材料成本按产成品数量分摊、当期工资和维护立即费用化”的简化政策，则已售木板材料成本 15、未售材料库存账面价值 5；**本期利润** = 60 − 15 − 20 − 10 = **15**。
- 期末现金 110 + 存货材料账面 5 = 115，相对期初净资产 100 增加 15；**利润 15 ≠ 现金净增加 10**。
- 所有 60 销售款必须来自买家账户；初期不能给无预算 NPC 一个自动补足余额机制。现实会计常将可归属的转换成本计入存货；本例采用简化期间费用法，须固定并在报表标注，不得与其他成本法混用。

可观察结果：库存未卖完 → 利润与现金不相等 → 可能无力维持下轮工资 → 减产/降价/融资/关闭。这是经济动态，不需随机触发“危机日”。

### 5.4 信贷 P2：严格延后

先完成不借贷的市场和资金循环。之后才能加债权、利息、抵押权、违约与清算。贷款本身不等于利润；债务本金不能重复计入企业收入；银行的存款创造是另一个复杂专题，不在第一轮偷偷实现。企业关闭时要有债务和工资未付的处理顺序，规则需随制度而变。

## 6. 社会形态识别：派生画像，而非解锁 [D07、D08、D11]

指标按地区、30 个**有效模拟日**的滚动窗口统计；离线冻结日不算有效样本。指标取 [0,1]：

```text
wageLaborShare        = paidWageLaborHours / allObservedProductiveLaborHours
marketProductionShare = goodsProducedForSaleQtyEquivalent / allObservedGoodsProducedQtyEquivalent
wageDependency        = householdsWithWageShareAboveHalf / householdsWithObservedIncome
privateControlShare   = productiveAssetValueUnderPrivateResidualControl / observedProductiveAssetValue
reinvestmentShare     = positiveOperatingSurplusReinvested / sumPositiveOperatingSurplus
```

不同物品不可直接以“件数”相加；`qtyEquivalent` 需要明确单位转换/价值权重，若没有可靠计价先仅展示分行业数值，不推出单一总比例。产权估值缺失时 `privateControlShare` 返回 **unknown**，绝不当作 0。家庭收入可兼有工资/自营/土地/资产收益。

**候选游戏判定参数（待实验调参）**：有效样本天数≥7；`wageLaborShare≥0.40`、`marketProductionShare≥0.50`，并存在连续的雇佣生产-销售-再投资循环；当窗口满足至少 7 个有效日可标注“资本主义生产关系扩张”，不是地区全体都资本主义。示例阈值仅是便于测试的默认候选。退出标注使用更低阈值/持续衰退（滞回），避免一天反复切换。**标签从不改变模拟规则**，只解释已经发生的关系。

若出现私人、家庭、合作、公共资产并存，显示“混合经济及各部分占比”而不是强制选一。技术发展阶段照旧由 `SettlementStage` 单独给出；可出现“农业技术 + 雇佣生产”、“工业技术 + 合作社生产”等组合。

## 7. 玩家角色、社会制度与可视化 [D08–D10、D12]

**经营者 5–30 分钟**：真实取得工位使用权 → 获得起始资金（测试地图预置，正式生存需合法积累/出资）→ 从可达供应者买原料 → 发布带工资的岗位 → 工人申请或拒绝 → 真实生产 → 以订单卖给有预算居民 → 看账本及库存 → 决定是否扩大产能。没有人申请就只能自己劳动或改变条件，不能强制村民上岗。

**劳动者 5–30 分钟**：寻找岗位 → 比较名义工资与生活必需品价格、通勤、工时和家庭照料 → 签约 → 完成一班真实劳动 → 获得款项 → 购买真实食物或退职。能发现高工资不一定意味着高购买力。

**合作社对照 5–30 分钟**：相同木材作坊与技术下，让两名生产者共同决策并按协定分配净收益，取消单独的外部剩余索取者；相同产品生产和市场竞争不意味着产权与治理相同。

最小 UI 只需“资产产权、现金、材料库存、未售库存、合同工资/班次、今日成交、为何失败、谁拿到收益”。主玩法仍由 Minecraft 方块、劳动动作和交易事件展示，UI 不要成为经济表格模拟器。

政策作为`Norm/Rule`的跨阶段扩展：最低工资、工作时段、欠薪处置、税制、社会保障、合作社治理等应实际修改交易有效性、成本、分配与行为；不能只给“劳动保护 +5”抽象 Buff。对强迫劳动、童工、殖民剥夺等历史主题，研究时标识伤害与制度限制，不作为低成本玩家最优攻略。

## 9. 12 个明确的模型实验与验收 [D12]

| 测试 ID | 输入/对照 | 必须断言的结果 |
| --- | --- | --- |
| EXP-S5-01 | 开店自营 vs 相同店铺雇工 | 均可交易；只有后者出现实际合同与工资，不因“有店铺”自动判资本主义 |
| EXP-S5-02 | 木材作坊数值种子（第 5.3 节） | 期末现金 110、木板库存 10、本期简化会计利润 15；买方现金减少60 |
| EXP-S5-03 | 订单无人买 vs 30木板售出 | 前者成交款为0、原物资仍在库存；不得自动卖空 |
| EXP-S5-04 | 工资账户不足、同样岗位 | 无有效工资预留就不得形成已支付工资/已生产班次 |
| EXP-S5-05 | 一人同日采集/照料/雇工三任务 | 总已占用工时不超过预算，不重复形成产出 |
| EXP-S5-06 | 买方余额不足、卖方订单存在 | 交易整体拒绝，双方现金与商品数量均不变 |
| EXP-S5-07 | 生产完毕存档、重读、重复 tick | 只存在一套 40 木板、一笔应付工资及唯一业务操作 ID |
| EXP-S5-08 | 同设备私人雇工 vs 合作社 | 产出方程一致，决策权和剩余收益归属按权利束改变 |
| EXP-S5-09 | 需求降低 60%，无新的资金注入 | 真实销量下降/库存积压/企业调整之一可观察，不触发无因随机“经济危机” |
| EXP-S5-10 | 有雇工但主要家庭自给 vs 雇工主导 | 区域显示混合关系，不允许仅凭一间工厂覆盖所有社会形态 |
| EXP-S5-11 | 旧 `DATA_VERSION=18` 存档升级 | 旧公仓、居民、材料与事件均保留；新字段安全默认未启用/未知 |
| EXP-S5-12 | 多人重复点击购买、卸载区域、100居民规模压测 | 服务端单次权威成交；未加载不跨区块实体操作；无无界积压或长期 TPS 异常 |

另外设计 3 组带固定随机种子的长期实验：A 资本积累 vs 消费；B 工人可选岗位多 vs 少；C 私人/合作/公共企业在相同生产条件的制度差异。每组保存状态、事件、库存、所有账户、工时和结果对照图。

## 10. 性能、网络和持久化预算

- 按聚落/市场区做索引和订单薄；不能每 tick 扫世界方块、全图经济主体或全日志。
- 推荐按约 1200 tick 的**市场快照窗口**撮合报价，约 24000 tick 的**经济日**结算工资与报表；这是默认调参建议，不是固定历史时间换算。频率先用纯模型压力测，再按真实服务端 MSPT 调整。
- 工作实体活动只在已加载区域执行；库存/金币/权限判定全部服务端权威，客户端仅收限量摘要。
- 增加 per-slice 上限（每聚落每次处理订单数、班次数、事件量、最大库存批次扫描数）；上限溢出延迟处理而非悄悄消失。
- `EventLedger` 当前事件为增长列表，正式长期 S5 启用前需评估定期快照/归档、按日索引与内存占用，禁止反复全量事件扫描。
- 金额用 `long` 最小货币单位，带正数、上溢、单一币种校验；不使用 `double` 存余额和工资。
- NBT 模式必须有版本迁移；未知或失效权利/账户记录须保守回退、留日志，不能擅自重新铸造资金或把旧公仓私有化。
- 验收：`./gradlew build`、`./gradlew runGameTest`、相关纯 JUnit，服务端 spark/同场景前后对照。现有本地测试环境根据 `AGENTS.md` 使用 JDK25 构建、Java21 运行。此研究提交没有运行构建，不能声明通过。

## 11. 尚未定论，但不阻塞第一条闭环

1. **货币初始发行与信用扩张**：P0 可预置测试账户并明确发行事件，正式生存经济须制定通用货币来源，S4 先使用同一货币层。
2. **跨地区价格和运输**：先局部市场，跨地区贸易复用 S4 路线和交易成本模型。
3. **法律人格与所有权**：股份制、有限责任、抵押和复杂破产法是 P2；P0 以权利束表示角色。
4. **会计制度**：第 5.3 节采用材料存货加当期工资/维护费用化的简化规则；后期可引入更严格成本分摊，但必须提供迁移与一致口径。
5. **政治经济学分析视图**：马克思劳动价值与其他经济学解释应独立计算，保持清晰前提；不把利润数直接贴“剥削值”标签。
6. **社会组织与工人集体行动**：先保留因果事件与契约后续接口，避免第一版引入不可解释的统一政治意志。
