## 0. 设计决议（先固定，避免阶段串台）

1. S4不是“领主制自动升级成资本主义”，而是**商品化、市场依赖、商人资本、商业制度、城镇空间**同时但不必同步增强的一组关系。S3的地租/劳役与S4的市场可共存；S5要另证生产资料控制、劳动关系、商品生产和资本再投资，不能靠开商铺或积累金币判定。
2. 研究阶段S0–S7是类型索引而非不可逆年代树；现有 SettlementStage.TOWN 只是设施/人口的技术与规模判断，不等于S4；不得把 SocialOrganization 自动替换为“商业制度”。
3. “市场”不凭空生产物资。买卖必需满足：**可出售批次 + 合法出售权 + 买方支付能力 + 运力与时间 + 实际交付**。报价、订单、承诺、预留、在途与已结算必须分开。
4. 食物富余不代表家庭买得起食物。保存家庭消费、留种/生计、租税、储备的优先权，允许富粮但贫困者挨饿的反事实（不预设每次都如此）；仅看聚落平均值会掩盖分配差异。
5. 商人的利润由真实购销和成本形成，能够亏损、破产和退出；商业组织可降低不确定性，也可能排斥竞争。市场发展不等于人人获益。
6. 遵守代码既有单一权威批次、来源链、事件账本、知情边界、服务端一致性和每日限频，尤其针对 #23 联机卡顿问题不能引入全村民逐tick市场路径搜索。

## 3. 三条正向因果链与两条逆向链

### C1 农业盈余→集市→分工

可卖剩余 = 总产出 - 已承诺口粮 - 播种/再生产材料 - 合法税租 - 最低安全储备 - 已预留订单（全为独立约束，不得重复扣同一物）。若家庭预计售卖带来的净收益超过保存/自用收益，则增加供货；工匠可用收入购买食物，减少自己的采食工时，交换网络扩大。若粮价涨得过快、家庭购买力恶化，分工会逆转。

### C2 地区差价→商人运输→市场整合

可售库存、可达路线、可信报价、价格差足以覆盖买入价+运费+税+风险+资金占用后，商人提交采购计划。真实交易使产地库存减少、销地库存增加，价差一般收敛；道路毁坏或掠夺可能令路线退出。**禁止商人瞬时知道另一聚落所有库存与价格。**

### C3 贸易规模→机构需求→商业组织→政治反馈

多次交易造成执约、护路、计量、仲裁等需求。地方势力/商人联合/自治机构可以建立规则并收费；有效治理可减少损失，特许与准入限制也可能抬高价格、集中资产。机构效果由成本与权利分配体现，不是统一的 +20% 生产力buff。

### R1 有粮食但缺购买力

聚落粮食库存高 → 某贫困家庭缺收入/财产 → 市场食物价格高于其预算 → 无法购买 → 饥饿和谈判/借贷/救济请求增加；公共粮储可缓冲但需真实库存及执行权限。这不是“价格越高全员越富”的简化模型。

### R2 资本集中与市场封闭

连续赢利 → 少数商人能支付行会准入、仓储或特许费 → 竞争者退出 → 进入门槛/议价能力上升 → 价格和政治权力可能改变；但外部竞争、制度改革或路线替代也能打破这种结构。只做概率与条件，不做“富人必然垄断”的硬编码。

## 5. 玩家可玩闭环：两地粮食交易（15–25分钟）

场景：河谷村有存粮和可出售余量；矿山镇缺粮并有真实购买能力/可交换工具；两地由安全度可变的道路连接。

1. 玩家到河谷村真实查看“可售40份粮食/预留口粮X/报价Y”，而非看到一个凭空的市场库存。
2. 玩家选择自己运输、支持商人一笔订单，或协助修路。所有操作需要合法出售授权和真实物资/现金/运力。
3. NPC商人检查自己已知的矿山镇旧报价、收货需求、费用和风险，选择报价/拒绝，记录原因。
4. 河谷村实际出库，货物进入唯一权威的在途记录（真实商队仅为其可视化代理），抵达后执行验收与收款；失败可恢复或记录真实损耗。
5. 矿山镇部分居民真实购买/领取粮食、库存改变；玩家可看到成交账单、价格和居民受益/受损。
6. 游戏下一日价格/路线/职业机会重新评估；相同货物不能再凭重登或双击完成第二次结算。

策略对照：A修路降损耗；B高过路税提高财收但挤压利润；C公仓优先留粮减少现金交易但提高缺粮时安全度。NPC不因玩家离开就停止所有抽象决策，但不能在未加载且未记录权威货物的区块伪造原版方块交互。

## 6. 最小经济模型（游戏参数，不是史学数值）

### 6.1 商品与家庭口粮约束

对商品g、商户a，最大可挂单：
    offerable(g,a) = max(0, physicallyOrBatchHeld(g,a) - subsistenceReserved - seedsReserved - taxesDue - committedOrders)

只允许对拥有出售权的批次计算；公共粮食不得未经共同体规则授权卖掉。需求必须区分必要消费和可延迟消费。

### 6.2 市场观察与价格

首版不用复杂连续撮合。每游戏日市场根据真实结算后的短缺信号更新可见参考价：
    shortage = clamp((targetStock - unreservedStock) / max(1,targetStock), -1, 1)
    targetPrice = basePrice * clamp(1 + 0.75 * shortage, 0.5, 2.0)
    nextPrice = clamp(currentPrice + 0.25 * (targetPrice-currentPrice), 0.85*currentPrice, 1.15*currentPrice)

注：系数 0.75/0.25/15% 均为初始游戏调参，不是历史规律。价格不凭空匹配买家。**实际成交价格**需卖方接受且买方余额足够；缺库存/缺信用/缺需求即零成交。价格使用确定性定点整数（例如1币=100最小单位），禁止浮点结算与负数/溢出。

### 6.3 订单成交量与利润

    q = min(卖方未预留库存, 买方有效需求, 买方可支付数额/成交单价, 路线实际容量)
    expectedNet = q*(destinationExpectedPrice-originPurchasePrice)
                  - transport - tolls - expectedSpoilageCost - opportunityCost

商人仅按**已知且带时间戳的价格报告**做预期，失败后更新认知，不能偷看另一聚落实时库存。成交流程先预留、再实际配送、验收、结算；账面净利润在实际成交后计算，未交货收入不计入已实现利润。若没有资金模型，S4-P0纯模拟可注入**明确初始资金事件**并核验总额，正式MC世界不得凭空产生金币。

### 6.4 商业化指标（观测用，不做升级开关）

- 商品化率 = 已成交本地生产商品数量/本地生产可核验总量；零产量时标为N/A。
- 市场依赖度 = 家庭通过购买获得的必要消费数量/可追踪的必要消费数量；注意赠予、公仓分配不是购买。
- 非自给就业率 = 实际工时中对外出售商品/服务的比例，而非仅看原版Villager职业标签。
- 市场连接密度 = 最近N日有完成交货的聚落有向连接数/可达连接数。
- 交易失败率 = 过期/拒绝/断路/无资金的订单数/提交订单数。
- 财富集中度 = 按经营资产或净财富计算的份额；需明确债务与土地评价方法，否则先不展示。
- 饥饿与可得性 = 库存充足但购买力不足的家庭占比；必须和真实消费/分配记录关联。

## 7. 数据契约、状态机与守恒原则

### 7.1 建议新增对象（先纯Java核心，后Minecraft适配）

| 数据对象 | 最小字段 | 约束 |
| --- | --- | --- |
| MarketNode | settlementId, resourceId, unreservedQty, desiredReserve, lastPrice, day | 聚落和商品稳定ID；数字不可负 |
| MerchantAccount | merchantId, ownerId, buyingPower, debts, authorizedLots | 资金和物权分离；不得读他人秘密余额 |
| MarketQuote | marketId, goodId, priceMinor, observedDay, sourceEventId, confidence | 有时效、能被误判；参考价不保证成交 |
| TradeOrder | tradeId, buyerId, sellerId, commodity, batchRef, qty, price, status, revision | 全局唯一ID；相同请求不能重复执行 |
| GoodsReservation | tradeId, lotId, qty, expiresDay | 同一批次各订单预留总量不超持有量 |
| InTransitLot | tradeId, sourceLotId, qty, destinationId, routeId, etaDay, lossProof | 唯一在途库存，不和出发地/目的地重复记账 |
| MoneyEntry | entryId, tradeId, accountId, signedMinor, cause | 每笔转账借贷两端抵消；不能虚造余额 |
| MarketInstitution | polityId, policyId, affectedMarkets, enactedDay, authorizedBy | 是否有效由制度权限决定，允许撤回 |
| TradeEvent | eventId, tradeId, phase, parentEventIds, ownerId, proof | 溯源、重放幂等、失败可解释 |

订单状态：
    PROPOSED -> VALIDATED -> RESERVED -> DISPATCHED -> DELIVERED -> SETTLED
                                \-> CANCELLED   \-> LOST / RETURNED
*状态分支是建议形态，具体代码需用枚举+合法状态转换矩阵实现。*

- VALIDATED检查源批次持有、出售权、需求、信任/信用或支付能力；价格只是条件之一。
- RESERVED是承诺量，**不是从源批次创造另一份库存**；DISPATCHED后由单一权威将源份额变为在途份额，不能双存。
- DELIVERED须有收货证明；SETTLED才释放卖方收入与税费；失败补偿有来源事件，不能依赖临时客户端状态。
- 重复处理同一tradeId+phase必须返回既有结果。失败、多人操作与存档重载须持久记录处理标记（tombstone）并允许重放。
- **注意跨SavedData和原版容器并非数据库事务**：仅写“二阶段提交”四个字不足以解决崩溃；第一MC切片必须限制在同一服务器/维度及可控加载范围，明确唯一权威账本、存档写入顺序与恢复逻辑，并用中断/重载实测；跨维度和非加载区块放P2以后。

### 7.2 记账不变量

- 物量：初始批次 + 有来源的真实输入 + 生产 − 真实消费/腐坏/损失/真实输出 = 当前各持有者 + 在途 + 已锁定但仍在原批次的份额（预留不可重复计算）。
- 币量：各账户余额 + 资金在途托管总额 = 初始发行/存入净额 + 明确发行 − 明确销毁（税款转国库**不是销毁**）。
- 同一ItemStack不能同时作为真实容器物品和SimulationWorld抽象批次；导入/导出继续复用原有适配链。
- 经济货币（账本）与原版绿宝石ItemStack不能在未实现兑换/托管审计时混称“同一笔资产”。P0纯模拟数字货币可以用显式初始头寸，MC世界P1先做真实绿宝石支付或可审计托管，不能免费生成居民钱包。
- 生产劳动、商队搬运、公共工程、照料使用同一有限工时预算；商人职业不是免费虚拟工人。

## 11. 性能与多人边界

- 价格/供需每日批量更新；市场信号事件驱动缓存；路线只在道路变化/定期时失效，复杂路网最短路不在每个村民的 canContinueToUse 里执行。
- 真实世界商品交接由服务端主线程核验，业务逻辑和纯Java模拟之间使用明确请求/结果接口；客户端只请求与展示，不提交自己算出的余额/价格。
- 抽象商队允许离屏推演，但不得凭空加载区块、修改未加载的原版箱子、生成额外实体；到达再以唯一在途货物交接。
- 一笔交易最多N条必要事件；玩家界面采用事件摘要，历史账本提供上限/分页或归档机制，避免保存全部市场报价快照引发存档膨胀。
- 对照 #23 联机卡顿研究：提交实现时提供相同存档、人数、路线、客户端帧时间及服务器MSPT高分位，不能只报TPS平均。

## 12. 冻结L2研究的条件与下一议题

达到L2可暂时冻结研究版本的条件：历史证据与游戏假设分层；3条物质→行为→制度链及2条逆向链；12维矩阵；至少1条15–25分钟真正可玩闭环；完整订单状态机及跨聚落交接风险说明；3正向对照+2反事实/故障试验具体可执行；S3/S4/S5不串台；与Fabric既有真实库存/存档/性能一致。

**仍待代码验证**：世界层统一市场协调器实际存储位置、跨SavedData/箱子的崩溃恢复机制、实物货币或虚拟托管的资金来源、商队路径/加载策略、旧存档迁移、单机+联机性能。研究定稿不宣称这些问题已经解决。

下一轮研究问题：**商人通过包买制控制原料和商品出售，与直接控制雇佣劳动有何不同？** 让S4→S5由生产关系变化产生，而不是自动时代事件。
