# 《文明演化》S0 原始社会综合设计、研究边界与封版条件（v1.0）

> **研究基线，尚非已完成的开发交付**  
> 日期：2026-11-04；当前 `main` 源码审查提交：`17296af707a08a334a94c4cb75b59472ec2dca5b`。  
> 工程：Minecraft Java 1.21.1 / Fabric（构建JDK和运行配置始终以最新 `AGENTS.md` 为准）；modid `coopcraft`。  
> 本文明确**哪些研究答案足以支撑S0 L2开发、哪些行为已经有代码、哪些还需要实机验收**。它不意味着已完成一个真实史前文明的复原，也不替代 `docs/civilization-design.md` 或源码。

## 0. 研究单元与“完成”的定义

S0不叫“石器科技等级0”。它以采集、捕鱼、狩猎、非固定规模的地方资源管理和生活互助为研究重点，允许移动、高度定居、个人保管、家庭供养、共享、长期合作与某些资源的限制使用等**多种同时存在**的组织方式。不能用阶段标签单向解锁制度和所有权。

**L1研究目录完结**＝D01–D12均形成问题、理论边界、主要证据、可玩接口。  
**L2研究设计完结**＝主循环、真实世界资源/劳动/信息及社会结果的连接、反事实实验、工程验收均有可审计规格。  
**S0软件完成**＝经过Gradle、JUnit、Fabric GameTest、开发探针、真实客户端和多人联机验证。**前两项不能冒充第三项。**

### 玩家体验的一句话

> 一个玩家加入或拜访会自主生活的营地，通过采集、加工、探路、分享、照料和公共项目参与社会；营地能在不同生态与人际条件下迁移、合作、争议、延续传统或改变规则。玩家离开后再回来，仍能从真实人物、物品、设施和事件看见可追溯的历史。

## 1. 固定12维总结（研究闭合，不是无争议历史断言）

| 维度 | S0核心因果机制 | 最小玩家玩法 | 当前缺口/可留下一时代 |
|---|---|---|---|
| D01生态、历史 | 地点资源量/风险/恢复→行程→取食与驻地选择 | 找到并分享可采地点、参与往返出行 | 实体地点知识、出行与迁居未完整接通；复杂生态可延后 |
| D02生产力 | 工具/技能/材料/加工工序与运输决定产出 | 采集、制作石器、维修工具、加工食物 | 更广工艺/织物/渔具先留知识接口 |
| D03劳动 | 个人生存+照料+学习+公共项目争夺有限工作时间 | 对生产和公共施工提供真实劳动 | 统一工作时段/冲突协调需实装 |
| D04资源权利 | 个人携带、家庭保管、共用设施和资源地使用权可分 | 提供材料、提出/回应共享请求 | 权利束分开记录，不让阶段标签自动赋权 |
| D05分配流通 | 采收→携带→家庭/公共/互助→消费/腐败、交换 | 援助、公共上缴、分配争议与易货 | 目前玩家向村民赠食实际入公共储备；需明确语义 |
| D06人口再生产 | 出生、年龄、照料、共同居住/分享/迁离 | 援助需要照料的居民；认识生活群体 | 实体照料未完整映射，家庭并非统一婚姻模板 |
| D07分化 | 资源控制、信息、知识、关系与继承差异→不必然成等级 | 在不同合作/产权中体验真实后果 | 更成熟阶级制度和世袭研究放后续单元 |
| D08治理规范 | 求助→反复互动→期待/规则→实际执行→修订/瓦解 | 参与公仓协商、公共项目、维护 | 临时职位、设施权利与维护待映射 |
| D09文化知识 | 观察、游戏、教授、实践、迁移导致传播与失传 | 学习工艺、传授地点、参与纪念/群体活动 | 首版强调人间知识传播，宗教教义不硬编码 |
| D10物质空间 | 庇护、火塘、食物加工、储藏、工具与携带成本 | 帮忙建造、使用和维护真实设施 | 原始设施外观和空间生活表现继续打磨 |
| D11危机变化 | 季节/短缺/冲突/外部联系→留居、迁出、合作、重组 | 寻找替代资源、参与迁徙协商 | 多轨迹代码和迁移实机映射待验证 |
| D12玩家体验 | 世界先自治，玩家观察、参与、改变条件而非直接指挥全村 | 20–30分钟三层可玩闭环 | UI语言、引导、多人和性能验收 |

### 学术防错规则

- 现代民族志提供**机制比较**，不等于所有旧石器人群的共同生活模板。
- “社会趋于平等”“财富差距”“耐久制度等级”“对他人劳动的控制”分别建模，不能以一个“阶级系数”代替。
- 性别分工的具体程度在人类学中存在不同证据与论争，不从性别强制锁定狩猎、照料或管理权限（参考 Lacy 2024 https://doi.org/10.1111/aman.13914 与劳动分工评论 https://doi.org/10.1016/j.evolhumbehav.2024.04.014）。
- 仪式或葬俗不能根据一件符号器物推断出通用巫师等级或神职制度。文化有自身的意义，不能全部转成产量加成。
- “共同资源”与“无人管的开放取用”不同；使用权、管理权、排他权和收益权要分别记录，参考 Ostrom 1990 https://ostrom.indiana.edu/courses-teaching/teaching-tools/ostrom-design/index.html 。
- 冲突可因实际条件产生，不能把每个营地默认引向战争，参考 https://pubmed.ncbi.nlm.nih.gov/39638956/ 。
- 本阶段的复杂性来自**少量真实行动的不同组合**，不是堆数百种物品、身份、强制事件。

## 2. 统一领域模型：把十多个专题接成一条社会历史

```text
Minecraft 真实地图/方块/库存/实体
      ↓ 被实际观察
资源地点、可达性、实际生活需求、居民知识
      ↓ 经过个人认识
人物可行行动、关系、权利、社会规范和时间约束
      ↓ 人物独立回应
生产/照料/旅行/交换/公共项目/冲突/学习的具体承诺
      ↓ 由服务端执行或明确界定的抽象模拟
实际方块与物品变化、时间消耗、重要社会事件
      ↓ 观察和传递给其他人
家庭安排、社会信任、技术传播、规则修订、迁居与历史
      ↺ 反馈到后续生产、选择与环境使用
```

**每一份物资批次在任一时刻只能有一个权威保管/库存记录**；真实物品/抽象批次跨界转移必须先完成来源转移再入目标保管者，失败时幂等回退。不要出现“抽象鱼已被吃掉但真实背包还有相同一条鱼”。

实体 AI 不接受一个“已在抽象核心中完成一整天生产”的虚构命令；要明确哪些动作必须在加载区块完成，哪些是只用于相对比较的背景模拟。

### 2.1 六个长期稳定、跨时代可重用的事实类别

1. `ResidentIdentity`：稳定人名/UUID、年龄与生命史、位置、知识及记忆。
2. `ObservedWorldFact`：实际资源、设施、材料、地图和其观察来源；不要全知共享。
3. `ProductAndAsset`：可溯源物品/批次、设施、携带容量、所有权与使用权分离。
4. `LaborAndCareEvent`：谁在哪里、何时、用何资源、实际投入什么时间。
5. `SocialRelationshipAndRule`：居住、亲缘、照料、互助、冲突、承诺与实际规则。
6. `HistoricalEvent`：来源、参与者、实际效果、事件之间的因果关系、存档幂等。

实现时优先映射现有 `simulation.Person`、`SimulationEvent`、`ResourceBatch`、`NormSystem`、`SettlementSavedData`，**不强制新增上述同名Java类**。家庭UUID归属不自动决定同居、照料或物资共用；可按关系边扩展。

## 3. S0七个游戏内闭环（范围内必须可见，不必各自开独立菜单）

### LOOP-01：个人生存与工艺
**发现需要 → 到真实资源点 → 采收或加工 → 携带 → 真正消费/储备 → 工具/技能状态变化**。无资源时显示为什么卡住；不会无中生有。现有石器制作与真实仓库是起点。

### LOOP-02：家庭照料与生活安排
**儿童/其他成员出现照料需要 → 已知可行者自愿响应 → 占用与采集冲突的工时 → 提供实际照料和食物 → 记录共同生活影响**。不靠固定夫妻家庭、不强制按性别分配；游戏首版可以极简的“照料时段+可视回应”。

### LOOP-03：多家庭分享与公仓
**个人/家庭取得食物 → 选择携带/共同使用/分享 → 请求、回应或拒绝 → 实际出入库 → 社会关系/规则反馈**。公共上缴≠给某一个居民的定向礼物，UI必须区分。

### LOOP-04：公共工程与临时协作
**生活/设施缺口 → 实际居民提出项目 → 他人提供材料/时段/运输/照料 → 真实逐块施工 → 使用/维护 → 争议或新规则**。项目不得自动拥有所有居民强制劳务权；建筑者与施工进度复用现有系统。

### LOOP-05：地理探索、交通与迁徙
**资源观察与知情差异 → 选择近采/远行/交换/迁走 → 路径和搬运成本 → 真实地点与人员关系变化 → 历史遗迹保留**。完整实现规范见 [生态与迁徙专题](ecology-mobility-and-contacts-v1.0.md)。

### LOOP-06：文化、学习和社会记忆
**有人看到某种做法 → 有条件地学习、模仿或被教授 → 练习耗费时间 → 形成差异 → 跨家庭/营地传播或失传**。首版至少让一个人因实际关系和可观察事件学到一项技能/资源位置，并在后续真实劳动中使用。

### LOOP-07：长期社会变迁
**不同资源/位置/关系 → 不同生产与分配结果 → 规则延续/变化/失效，生活单位分合，聚落兴衰**。保持多轨迹与逆转；所有长时模型通过多个固定种子对照测试，不得把“原始→农业→城镇”写成社会制度必经解锁表。

### 两个不阻塞 S0 L2的增强方向

- 文化艺术、歌舞、宗教/纪念活动的多样表现：先保留可见文化活动和事件记录，具体仪式系统与声画资产可在艺术打磨阶段迭代。
- 成熟暴力、领土战争、长期首领世袭和强制贡赋：S0只需支持具体资源使用争议、调解、退出及必要自卫；后续社会形态再研究战争组织和国家征役。

## 4. Minecraft 20–30 分钟试玩脚本（用于验收，不能硬触发剧情）

**0–5 分钟：**玩家抵达营地，看见已知成员采集、制作、交流和生活，右键能看到“当前行动/原因/阻碍”。  
**5–10 分钟：**真实短缺出现或正在存在，玩家认识一户需要帮助的生活小组，发现公仓与远处浆果地点的关系。  
**10–20 分钟：**玩家可选：实际采集、给公共仓储粮、向一名居民分享资源地点、协助建筑或什么都不做。每条路都有物资、时间与信任的实际边界。  
**20–30 分钟：**部分居民可能改变短期计划，某项建筑暂停/恢复、一次分享得到回应、一条资源信息获得验证；玩家通过自然语言解释和真实场景看见改变。

**重要：不必保证在第20分钟一定出现事件。** 用不同测试初始条件人为准备可重现问题，生产服仍由实际事实驱动。该流程是对玩法是否容易理解的验收场景，不是任务脚本。

玩家不能任命全村领袖、直接编辑“生产关系滑块”、在未获社会许可时控制陌生家庭储备。居民拒绝不应被当成NPC功能故障；UI需说明合理原因。

## 5. 现有 Fabric 1.21.1 代码的分层接入清单

| 文件/系统 | 当前已存在 | 应当增量建设 |
|---|---|---|
| `LaborAllocator.java` | 根据已加载成年居民和性格做基础分工 | 把角色视为技能/偏好而非每日硬职责，增加可暂停/恢复的具体任务选择 |
| `VillagerWorkGoal.java` | 饮食、采集、工艺、建筑与寻路 | 任务原因、工时互斥、照料与出行可见性；真实完成才入账 |
| `SettlementNeeds.java` | 实际饱食与进食 | 需求事实/位置/受影响人只读快照，不复制食物账本 |
| `ConstructionPlanner/ConstructionSystem` | 蓝图和逐块工程 | 需求驱动项目、非强制承诺、延期与维护；已完成方块不因延期退款 |
| `SettlementSimulationService.java` | 抽象经济与真实Minecraft数据映射，限定已加载实体 | 显式事件桥接、避免时间重复扣减和无效远处实体结算 |
| `simulation.NormSystem` | 提案、知情传播、公仓领取规则、监督劳动 | 公共工程和资源使用规则扩大到更多实际行为，但不自动开会 |
| `VillagerInteraction.java` | 观察居民和赠送真实食物 | 将“公共捐赠”和“定向帮助”语义分清；增加资源地点分享/协作请求 |
| `SettlementStages.java` | `PRIMITIVE/AGRICULTURAL/TOWN` 单向进度标识 | 里程碑与当前技术/生产/分配/治理多维状态分离，需独立兼容评审 |
| `SettlementSavedData.java` | 成员、年龄、资源事件、规范与工程持久化 | 资源地知识、个人行动承诺和动态同住/照料记录，版本迁移要保旧存档 |
| `tools/probe` / YAML卡 | dev-only 实机UI检查 | 增加营地缺粮、施工暂缓、赠食语义、保存重载的测试卡 |

`AGENTS.md` 当前明确“**构建 JDK 25 / 目标字节码 Java 21**”。因此不再口头简称为“Java21构建”。mod运行环境、Loom与映射应依照最新项目文件，禁止偷换NeoForge或Yarn示例。

## 6. 数据、空间与游戏性能约束

- NPC只有有限的观察、计划和短期记忆；远地信息必须沿实际联系人和路线传播，消息可以过期。
- 个体的承诺、照料、学习、社会协商和实际制作共享有限活动时间预算；**承诺不是成品**，开始动作不能立刻结算产出。
- 每个真实物资批次的物理保管权威明确，抽象批次与实体物品转移幂等。
- 不全局强制加载区块；远处营地的长时实验只用于社会模拟模型，尚未实体对接的行为不得被宣称已在世界发生。
- 只在有限规划周期/事件改变时调整任务；不让所有NPC每tick重复扫描所有成员或整片地形。
- 多人客户端只能请求，所有库存/行为/规则变化在服务端校验。
- 当前多人项目具有网络波动与掉帧关注项，新增社会模拟必须给出主线程profiling和网络包大小、频率的回归测试。
- 容错：玩家中途退出、村民死亡、资源枯竭、路径失败、库存满、半完成建筑、旧NBT存档与双重加载都不应丢物、双算或卡死。

### 软件真正封版前必须有的可验收事实（当前未在本研究中执行）
- [ ] **P0** 已加载营地在无玩家操作时完成完整食物采集→库存→消费闭环，饥饿/资源耗尽后不死循环。
- [ ] **P0** 玩家向居民帮助与向公仓捐赠的语义正确，物品来源及结果真实。
- [ ] **P0** 缺粮/照料/建造三需求冲突中的时段调度，不会一人同刻双重生产。
- [ ] **P1** 至少一个真实可观察的家庭照料和非亲属互助行为。
- [ ] **P1** 公共工程能在真实资源不足时暂停、恢复，承诺/物资/方块不重复结算。
- [ ] **P1** 至少一次社会规范修订实际改变当前或下次真实领取。
- [ ] **P1** 玩家探索到一个真实可采资源点，NPC只在获知后才可能去验证；信息可能过时。
- [ ] **P1** 学习/传授至少一个真实劳动技能或资源地点信息，离开再回来仍然生效。
- [ ] **P1** 多个不同资源/信任种子的实验产生可解释的多种结果，包括分裂、迁出或明确的留居选择（可先为独立模拟验证）。

- [ ] **P2** 文化纪念/装饰等可见行为与历史事件连接（不必添加复杂宗教教义树）。

## 9. S0停止发散的规则与下一阶段入口

- 没有明确玩家行动、NPC自治、真实物资/社会反馈和实验检验的“有趣历史名词”，只作为参考条目，不新增一套核心系统。
- 原始社会特殊婚制、全面宗教史、所有地域器物谱、所有动物、完整世界战争、万年人口微观模拟：**不属于S0 L2封版阻塞项**。
- S1需要新增的是**长期耕地投入与土地使用规则**，而不是重写家户、仓储、劳力、照料和集体项目；
- S2着重组织性强制、贡赋与大规模组织，不假定任何早期社会必然有奴役；
- S3研究领地与叠加地权，S4研究商贸价格，S5研究雇佣劳动和资本流通，S6研究公共/合作治理；
- 同一条 `Task → Product → Claim/Use → Allocation → Outcome` 因果链可以被不同历史形态用不同权限和规则复用。
- 阶段性冻结是**研究管理**，不代表禁止日后研究新考古证据或修正明显错误。
