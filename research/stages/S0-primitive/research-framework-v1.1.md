# 《文明演化》Mod：原始社会统一研究体系与工程对接 v1.1

日期：2026-10-29  
定位：**研究架构补充稿**，不是替代已有主设计、不是要求一次性实现全部内容。  
工程定位：已连接 GitHub `ThySummer14/coopcraft`，Minecraft Java **1.21.1 + Fabric**。`gradle.properties` 记录 loader 0.20.1、Fabric API 0.116.17+1.21.1；`fabric.mod.json` 运行 Java 21。README 说明当前 Loom 构建工具链需 JDK 25、产物目标 Java 21，应按实际仓库配置运行，不要擅自改为 NeoForge。

## 0. 为什么需要 v1.1

此前研究依次讨论了生态、生产、分配、人口、亲属、社会规范、文化、聚落、所有权与权力，覆盖面已足够，但顺序偏专题化。今后改用「**核心因果问题 → 前置条件 → 个体行动 → 群体结果 → 规则反馈 → 可验证证据**」来安排研究。不能用增加 NPC 属性或新增一栋建筑代替解释机制。

**总命题：** 在资源有限、信息局部、个体差异、社会联系与既有规则的条件下，居民通过劳动、分享、合作、冲突、协调和迁移维持共同体；这些互动怎样形成、稳定、改变或瓦解生产关系与社会制度？

目标不是让所有营地自动进入下一社会阶段，也不是让原始公社只能向阶级社会演化。

## 1. 统一因果体系（五层循环，不是时代树）

1. **物质条件**：生态斑块、季节、地形、资源、生产资料、人口、劳动时间、交通与建筑。
2. **主体行动**：居民需要、知识/不确定性、技能、风险、家庭照料、劳动选择、分享与迁徙。
3. **社会关系**：亲属、信任、互助、劳动分工、产品流动、资源使用/收益/排他权、实际外部选择。
4. **制度与共同体**：约定、规范、领导、执行、监督、争端解决、规则变更，受现有生产关系约束。
5. **历史再生产**：技能传播、出生死亡、代际传递、迁居/分裂、制度与空间形态的长期变化。

每层以事件、资源变化和决策结果反馈前后层；不能只用抽象文明值驱动。

## 2. 前七轮专题的依赖关系

| 研究主题 | 依赖什么 | 产生什么 | 与制度演化的关系 |
|---|---|---|---|
| 自然生态与季节 | 世界地形、时序 | 食物/材料可得性、风险 | 决定独立生计与退出是否可行 |
| 生产与劳动 | 资源、技能、工具、时间 | 产品、劳动贡献、可储存剩余 | 产生分工、合作与利益争议 |
| 消费与分配 | 真实批次、需求、分享动机 | 生存结果、赠与/拒绝事件 | 重复互动产生分享规范 |
| 人口、家庭与照料 | 生存、家庭网络、劳动时间 | 年龄结构、照料负担与供给 | 影响家庭优势和群体延续 |
| 知识与文化 | 接触网络、实践、教学成本 | 技术能力、共同记忆与观念 | 改变生产力与规范传播 |
| 聚落与运输 | 材料、劳动、环境、使用权 | 设施、固定投资、通达性 | 影响资源控制、迁居成本 |
| 财产与权力 | 产品、设施、关系、承认与执行 | 资源控制、组织能力与依赖 | 规则能够稳定化、继承或被抵抗 |

横向原则：个人物品所有 ≠ 私有生产关系；资源余量 ≠ 必然阶级化；首领 ≠ 国家；习惯 ≠ 普遍强制法；技术时代 ≠ 社会形态。

## 3. 用一个统一的「行动情境」连接多个系统

借鉴 Ostrom 制度分析框架，将重要行动组织为 `ActionSituation`：

- **问题**：谁面临怎样的实际矛盾（例如公仓不足）？
- **参与者/角色**：当事家庭、管理者、潜在帮助者、监督者；可临时变化。
- **信息**：每人确实知道什么，来源、时效与可信度如何；不得全知。
- **可选行动**：索取、赠与、拒绝、协商、监督、离开、违反、遵守。
- **可行性**：资源/时间/路径/工具/风险；禁止凭空执行行动。
- **当前规则**：已被哪些人承认，谁有执行权，违反成本是什么？
- **结果**：真实物资变化、时间成本、关系变化、群体支持变化。
- **反馈**：未来遇到同类情境时，居民与规则是否有变化？

`行动情境` 是逻辑结构，不一定新增大量 Java 类；先复用现有 `civilization.simulation` 的事件、居民、批次与规范流程。

## 4. 居民自主决策：必要的最小模型

**不是“贪婪 +10% 不分享”这种一刀切模型。** 居民的行为取决于真实需要、个人偏好、既有义务、关系、实际可行行动与主观信念。

建议每次需要选行动时：

1. **触发**：饥饿、生产机会、请求、纠纷、家庭照料或发现信息。
2. **生成可行行动集合**：按当前物品、路径、权限、时间和健康过滤掉不可能行为。
3. **依个人已知信息作出预期**：对收益、风险、对方反应存在不确定性；不能读取世界真相。
4. **评价选项**：生存保障、家庭义务、信任/互惠、习惯压力、风险与劳动成本等分项，而非单一固定人格分数。
5. **选择并执行**：有有限理性、有限探索；失败也是真实反馈。
6. **事件结算与记忆**：库存、饥饿、能力、关系、权利、信誉发生相应改变。
7. **长期策略调整**：某些居民可以改变习惯、重新评估伙伴或迁移。

伪式：

`score(a, person, context) = perceived_survival_gain + household_value + expected_cooperation + normative_approval - expected_risk - labor_cost - transition_cost`

不是普遍的人类效用定律；所有权重只能作为假设参数，并通过情境测试校准。

**人格只是偏好修饰，不得代替实际处境。** 例如高自私的猎人也可能因为家庭无粮、亲属请求、未来合作风险而分享；“慷慨”居民也可能因库存不足而拒绝。

## 5. 制度怎样涌现：三个不同层次

**操作层（operational）**：今天如何领取食物、在何处捕鱼、是否分享。  
**集体规则层（collective-choice）**：谁有资格规定领取顺序、是否设上限、如何监督、怎么变更。  
**规则制定资格层（constitutional-like）**：谁可以参与协商、哪些居民具有决定或监督资格、管理职位能否继承。

原始社会可以形成这三个层次的规则，但它们不意味着拥有成文法、现代宪法或国家。

**形成规则并非“多数人偶然做了同样行为”**。规则要有明确情境、共同期待、知情与承认范围、执行/纠纷成本、实际影响和跨时间稳定性。

最低演化闭环：

`真实短缺 -> 家庭请求与拒绝 -> 信息在关系网络传播 -> 部分居民提出公共分配方案 -> 参与、协商、反对、监督 -> 生效或失败 -> 真实公仓分配策略改变 -> 再次短缺时检验 -> 修订、稳定或失效`

此链条在独立 Java 模拟中已有雏形。下一步是**映射到真实村民行为与 UI 观测**，而非再写一套无关的“政治系统”。

## 6. 现有 Fabric 项目情况与差距（基于仓库文档，未经本轮本地构建验收）

已在 README / `docs/civilization-design.md` 声明：

- 公共仓库与真实食物消费、工具制作、采集/施工、原始共同制度、人格与首领、聚落名册。
- 纯 Java 独立模拟中的资源批次、共享/拒绝、规范提案与修订、双营地迁徙、家庭与照料、知识传播、以物易物。
- 显式 Minecraft 真实物品与模拟库存转换、`SettlementSavedData` 版本 9、限定生存结算；JUnit 和 GameTest 测试记录。

**最关键差距：** 真实 Minecraft 聚落尚未完整运行抽象模拟中的生产、成长、亲属、知识和规范；当前仅有限生存结算完成映射。这里必须优先对接，防止出现彼此独立的两套“社会”。

应明确逐项核对：

| 旧实现/约束 | 不要求推翻 | 研究上的升级方向 |
|---|---|---|
| `primitive_commune` 作为默认制度 | 是原型的可运行初始状态 | 以后允许居民通过实际规则实践改变局部规则；不是永恒公有魔法开关 |
| 首领按社交/人格等评分继任 | 保留兼容与初始行为 | 转为社会支持、实际组织能力、职能范围与接受/拒绝共同起作用 |
| 每个聚落自动建一座固定石屋 | 可作为旧原型 | 根据实际生活缺口、材料、地形、劳动与共识产生项目 |
| 个性由 UUID 决定 | 稳定个体初始特征 | 同时允许经历影响信任、偏好、学习和政治态度 |
| 已实现的公仓与资源守恒 | 继续沿用 | 保持统一权威库存、显式交接，不得再做第二套账本 |
| 仅加载成员进行生存结算 | 安全、可验证的初期限制 | 未来研究远处人口与离线推进的一致性，但不应偷渡“离线凭空产粮” |

注意：仓库 README 提到当前 Loom 构建可能需要 JDK 25，但游戏运行和目标字节码仍为 Java 21；遵循已有工程 CI 和 Gradle 约束。

## 7. 接入同一世界的工程契约

**服务端权威；每个资源只结算一次；事件可追溯。**

- `SimulationCore`：独立的确定性社会模型，不直接接触 Minecraft 方块或客户端；现有类优先复用。
- `WorldAdapter`：把真实方块、容器、实体和路径结果转换为核心可理解的输入事实，并将核心行动计划映射为 Minecraft AI 行动。
- `SingleInventoryAuthority`：同一批物资在真实容器与抽象账本之间只能有一个权威；转入转出必须原子化或可回滚。
- `DecisionAndAction`：行动有 `intent -> validated -> executed/failed -> event` 生命周期；失败不能假装成功或消耗双份物品。
- `EventLedger`：追踪来源、执行、被影响者、资源/关系/规范变更。日志还需提供人类可读解释和便于 GameTest 的结构化引用。
- `Persistence`：保留 UUID、`SettlementSavedData` 版本迁移、重复读取幂等性；不得破坏既有旧存档。
- `UI`：玩家看到的不只是“制度名称”，还应看到居民为某项规则提供的理由、谁支持/反对，以及它是否真的改变库存与行动。

示例：玩家/村民从公共仓库取鱼时，真实物品、抽象库存与社会事件应共享一个权威交易 ID，重复游戏事件或区块重新加载不能重复扣除或重复发放。

## 8. 以一个纵向切片取代横向堆功能

**场景：寒季公仓不足。**

1. 资源减少导致真实仓储下降；
2. 两个家庭需求不同，向仓库请求产品；
3. 管理者/居民按已有分配规则处理，发生可追溯的发放或拒绝；
4. 受到影响的居民形成不同立场；信息经实际交往传播；
5. 居民提出具体可执行的分配调整（如照料优先、领取上限、管理轮换）；
6. 参与者协商，结果可能是执行、失败、退出；
7. 新规则实际改变下一次发放，并消耗监督协调时间；
8. 玩家在游戏里看见行动、仓库变化、争议记录及关系反馈；
9. 保存重开后，不重复发生一次交易，不丢失规范状态。

**验收**：无需剧本固定触发同一结局；同一初始状态同一随机种子可重放；不同资源/关系/信息条件能够产生差异；每次物资流动守恒；规则发生了可验证的行为效果。

## 9. 研究优先级（按依赖，不按兴趣跳跃）

- **R0 / 社会模拟公理和可观察性**：实体与批次唯一身份、真实事件、局部信息、守恒、时间和权利语义。已有基础，先审计。
- **R1 / 生存与生产再生产**：需求、劳动、食物、照料、技术、生态压力；验证营地能自持。
- **R2 / 行动者和社会网络**：有限理性、记忆、亲属、信任、交往、请求与拒绝；验证不同人对同一矛盾的不同反应。
- **R3 / 规则与组织产生**：提案、参与、监督、约束、争议、修订；验证规则改变真实经济行动。
- **R4 / 长期制度与空间**：代际、技能、聚落投资/迁徙、制度稳定和退化。
- **R5 / 社会分化**：资源排他、继承、剩余控制、劳动依赖、外部选择、反向治理机制。
- **R6 / 比较历史与阶段过渡**：同技术条件下不同制度的多种轨迹，先完成原始阶段，再考虑后续社会形态。

一次研究新题必须回答：它连接哪几层？有哪些前置数据？它以什么行为影响游戏？如何检验其结果？失败条件是什么？是史料事实还是游戏假设？是否与已实现代码重复？

## 10. 近期交给 Agent 的任务（优先级建议，非操作授权）

1. 对现有仓库 `civilization.simulation`、Minecraft AI、仓库/存档适配进行现状与数据流审计，画出**哪一套系统对每个状态负责**。
2. 选择「公仓不足→请求→协商→规则影响下一次分配」作为真实世界纵向切片；逐步接入，并给出 GameTest、JUnit、一次实机录像/截图或事件日志验证。
3. 对现有原始公社默认值、固定首领选择与建筑规划添加研究标记，禁止因新设计直接删除兼容旧存档的逻辑。
4. 仅在前述闭环达标后引入资源排他、管理职位轮换或继承等高级规则。
5. 对未来提案建立明确的 P0/P1/P2/P3 依赖、测试及性能预算，不再只按功能名称安排优先级。

## 11. 研究证据与模型边界

- 经典文献与理论框架用于提出可检验的机制，不是固定历史脚本。
- 民族志中的现代群体不能直接当作史前人类的单一模板。
- 避免把「观察到相关性」写成「固定必然因果」。
- 由模型自由生成的结果只能证明程序规则可以产生某种现象，不等于证明真实历史就是如此。
- 不能通过把居民无知、无能或强制平等预设成常量，来“验证”某个想要的制度结论。
