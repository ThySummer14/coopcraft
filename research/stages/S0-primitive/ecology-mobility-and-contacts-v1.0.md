## 1. 理论上重要的六件事

1. “采集狩猎者”不是一种固定居住模式。**居住地迁移**（residential mobility）与从据点往返资源地的**专项行动**（logistical mobility）必须分开建模。
2. 食物与材料的空间分布、预期产量、交通、季节与风险决定日常行动成本，不由预设“文明等级”决定是否迁徙。
3. 对资源地的**实际知识**、观测时间和可信程度不等于系统读到的实际资源数量；信息通过本人探索、亲友、传闻和营地联系传播。
4. 居住群体可以季节性聚合或分散，家户之间存在可重组联系；迁往其他营地不是“历史倒退”。
5. 物品、技术、人员和社会关系可以沿不同范围传播；有跨群体联系不必有货币或商人职业。
6. 争执与暴力也可能发生，但不应从资源竞争自动推导出战争、国家、奴役或单一战争文化。

## 3. 与现有 Minecraft 的最小落点

### 3.1 不重写 Minecraft 生物群系

第一版只读取：
- 方块位置、可加载性、是否可达、已有甜浆果丛的成熟状态；
- 已登记资源点和真实方块采集/破坏/产物；
- 聚落中心、床/火塘/公仓/工位和村民真实工作状态；
- 玩家探索和分享给居民的信息事件。

不凭空模拟一个“地图上有无限浆果但世界里没有”的资源库存。抽象模拟的资源斑块若用于实体模拟，必须存在**明确的实体映射和唯一结算边界**。没有物理产物的仅能作为预测或背景，不能直接提供真实食物。

### 3.2 `ResourceSite`：已知资源地点，不等于资源库存

概念字段：
```java
record ResourceSite(
  UUID siteId, ResourceKind kind, ResourceLocation dimension,
  BlockPos center, int approximateRadius,
  long lastActualObservationTick, double observationConfidence,
  UUID discoveredBy, SourceEventId evidence,
  SiteAccessRule accessRule
) {}
```

已观察的状态应与真实状态分离：`KnownSite(personId,siteId,knownYield,observedDay,confidence,sourcePersonId)`。可让不同居民掌握不同的过时信息，不读取未共享坐标或未加载世界的资源数。

S0首版只实现一个实际可玩的资源：**自然生成的成熟甜浆果丛**。后续捕鱼、狩猎、不同野生植物、石料源使用相同地点接口但各自物理实现，不能为了图省事把鳕鱼或牛肉直接抽象为“附近资源+5”。

### 3.3 地点的采集、恢复和无效观测

```text
玩家/NPC到达 -> 真实方块/资源状态已加载 -> 确认是否成熟/可采
            -> 实体进行采集动作 -> 实际入包 -> 唯一库存/来源事件
            -> 更新当前居民的观察与知识
```

- 已知资源地枯竭不应导致每个 NPC 无限重复走过去；应记录最近失败及有限回访冷却。
- 成熟度变化可直接依赖已有方块机制。若未来引入新的“资源恢复”参数，须按地点/群系配置且在加载时惰性计算，**不重复生成已经被玩家采掉的方块和物品**。
- 存储 `observation` 时不把其误当成“所有居民都知道”，更不能以资源地标签自动强制排他使用。
- 尽量不要每 tick 扫描大半径地形；在新发现、采收、失效和有限规划周期触发重新评估。

## 4. “继续在此生活”与“迁走”是多种选择，不是一个按钮

居民可考虑：
1. 继续从近处采集；
2. 结成短期小队，远距离采集后回营地（专项出行）；
3. 与邻近营地共享信息、请求帮助或进行实物交换；
4. 部分家庭搬离，建立季节性分营；
5. 整个营地逐步搬迁（最后才考虑，且不必须）。

**迁移意愿**不能简化为 `food < 5 → teleport whole tribe`。至少考虑：
- 旧地点的预期长期收益与危险，不把一次短缺等同资源永久枯竭；
- 候选地点是居民实际知道且有可信来源，不是读全地图的最优解；
- 行程距离、照料负担、工具和物品的实际搬运成本；
- 留在原址的建筑投资与当前使用权；
- 其他成员的依赖、外部联系人和是否同意；
- 迁移失败/途中资源耗尽以及返回选项。

未加载区域的**抽象家庭迁徙**与真实加载区域的**实体寻路迁移**必须分开：已存在独立模拟双营地迁徙可继续作为高层预测，但第一版实体接入仅限加载区域、可验证的路径和有明确起终点的搬运，不追赶离线移动。

## 5. 玩家探索的社会价值

**玩法一：发现并分享一处食物地点**

1. 玩家主动在野外发现成熟甜浆果丛，实际观察并记录地点。
2. 回营地向一位居民分享已知位置，居民根据相信程度、资源急迫性、距离和照料负担决定是否出发。
3. 目标存在且可达才能实际收获；NPC无法从遥远未加载地形凭空挪走作物。
4. 成功后形成“信息由玩家传来 → 居民验证 → 实际生产”的因果链；失败可能降低特定地点可靠性，却不直接判定玩家撒谎。
5. 探索发生的效用可通过避免一次短缺、降低寻路次数、扩展已知采集范围体现，而非经验条必然加分。

**玩法二：陪居民走一次专项出行**

玩家和已同意的居民共同前往较远资源点，往返时间和携带量有实际成本。中途居民可能因饥饿、危险或照料任务退出；共同到达则产生探索记忆和工作事件。无需昂贵的自研团队战斗AI，先复用现有追随/路径与工作状态。

**玩法三：营地讨论搬迁**

真实物资和资源地状态引发迁移议题；玩家可以主张“留下修仓”“找新营地”“先派人探索”，但最终由受影响成员分别选择。保留新旧地点的建筑、库存来源和人员关系，不生成一个全新、没有历史的“升级聚落”。

## 6. 营地间关系：从交换和探访开始，不从战争开始

共享底层：
- `InterCampContact`：双方居民联系人、相互信任、最近接触；
- `RouteKnowledge`：路线、时间、风险、信息年龄；
- `VisitEvent`：探访、学习、分享信息；
- `ExchangeEvent`：真实物品双向转移、无现代货币预设；
- `DisputeEvent`：阻止使用/指控/请求补偿/调解/退出；
- `ThreatEvent`：可选的边界冲突、袭击和保护行为，**非固定自带战争按钮**。

历史研究中也有暴力证据和和平跨群体交流证据。不得从资源短缺直接推导一个固定几率触发“部落战争”；必须建立实际行为者、空间接触与行为后果。S0首版重点是探访、信息传播、易货和避让，冲突机制先有拒绝进入、争议与重新协商即可。成熟战争组织留到后续社会形态也可以研究，但不应假定战争起源一定在更晚阶段。

## 7. 文化、地方知识、仪式：少量真实行动，不做玄学科技树

本专题要求的文化可见性：
- 一个居民从别人处学习资源地点/工具工艺；
- 共享火塘作为食物准备、交流和合作的空间，不自动宣称“宗教场所”；
- 营地使用地方名称、装饰或纪念物记住重要事件；
- 仪式/纪念可作为自愿集体活动，消耗真实时段/物资，改变已参与者的关系与共同记忆；不会直接“祭祀+10%产量”。

考古中对远古象征性行动的解释存在争论，见 Bahn 2012 https://doi.org/10.1093/oxfordhb/9780199232444.013.0023 及 2024 Manot Cave 研究 https://pmc.ncbi.nlm.nih.gov/articles/PMC11665919/ 。不应该将特定宗教教义作为所有早期社会必有组件。

## 8. 实验矩阵

| 实验 | 单独调整的条件 | 观察对象 |
|---|---|---|
| E01 近处资源丰富/衰竭 | 已加载有效成熟浆果丛数量 | 行程、食物产出、回访频率 |
| E02 信息可靠/过期 | 个人观察时间与已知地点一致性 | 无效出行、转移知识与协作效率 |
| E03 道路成本 | 距离、可走路径的阻断 | 专项出行与近地采集比例 |
| E04 搬迁代价 | 携带负担/设施损失成本 | 留居、外出、家庭迁出差异 |
| E05 跨营地联系人 | 已知路线与互信关系 | 探访和实物交换是否可行 |
| E06 共享规范不同 | 社会规则、其他不变 | 信息传播与食物保障结果 |

必须包含：无路线不会瞬移、两个人不从同一粒方块复制收获、资源地点故障不永久卡住行为、村民不全知、原营地建筑不会搬迁时神奇消失、卸载/加载与存档幂等、多人联机玩家说谎/重复提交不绕过物资账本。

## 9. S0阶段边界

S0必备：**已知资源地点、地形探索、有限采集路径、信息传播、日常短缺反馈**。  
S0研究完成但可延后实体实现：家庭分裂/季节聚散、长期跨营地迁移、复杂捕鱼及网具、地理更精细季节系统。  
S1深入：永久耕地与播种循环、灌溉、长期土地投入和更细的粮仓建造组织。  
S2+深入：强制征役、政治机构、规模化战争和征粮治理。  
S4/S5深入：商队、市场价格、资金周转、物流合同与资本循环。

不得为了一个“真实原始社会”无限加动物、作物、仪式和方块数量。**通过玩家观察、决定、行动和后果闭环判断是否够用。**
