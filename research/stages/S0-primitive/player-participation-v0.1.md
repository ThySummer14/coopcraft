# S0｜原始社会：玩家参与、居民自治与制度涌现（v0.1）

- 日期：2026-11-04
- 研究范围：S0 / D03 劳动、D05 分配、D08 规则、D09 社会学习、D12 玩法
- 文档性质：游戏设计提案，未指示 Agent 立即实现。以**源码和现有 GameTest** 为实施依据。
- 技术定位：Minecraft Java 1.21.1 + Fabric；沿用现有 `civilization.simulation`、`MinecraftStockpileAdapter`、`SettlementSavedData`、工作目标、规范协商和事件账本。
- 依赖：[研究框架 v1.1](research-framework-v1.1.md) / [跨时代总纲](../../framework/cross-era-master-v0.1.md) / [当前工程主线](../../../docs/civilization-design.md)。

## 设计命题

让玩家不是操纵一群听令 NPC，而是在自主生活的共同体中通过劳动、互助、传授、交流、设施和公共协商留下长期影响。**真实感放在物资、劳动成本、权利和行为后果；便利性放在 UI、微观过程和重复操作。**

## 三层嵌套玩法

| 层次 | 玩家操作 | 世界的实际变化 |
|---|---|---|
| 当日生存（几分钟） | 采集、烹饪、帮助搬运、做工具 | 真实库存、工具、劳动时间和需求变化 |
| 共同体参与（几个游戏日） | 认识邻居、协作、照料、参与公共事务 | 互助、知情、信任与规则实际执行 |
| 历史演化（季节与世代） | 长期影响生产、教育、建设和协商 | 技术传承、聚落空间、制度延续或衰退 |

设计要求：玩家不参与时，NPC 仍独立生产、消费、分享、争议和协商。玩家必须能自由离开营地探索 Minecraft 原版世界。

## 玩家最初30分钟的可玩情境（不是脚本）

1. **观察营地**：看到火塘、公共储备、外出采集、制作工具和住宅施工；不强迫阅读 20 个管理面板。
2. **发现真实需求**：某居民粮食不足或缺制作材料。右键村民可以看到“当前目标、原因、阻碍”。
3. **提供帮助**：玩家送入真实物资、协同采集或共享已知资源点。NPC 接受与否受需求、权利、风险与关系影响，不是统一好感加成。
4. **社会后果**：家庭短缺缓解，居民记住重要事件；若已有人提出公仓规则调整，玩家也能表达意见、出资或协助执行。
5. **生活继续**：即使没人开会，营地仍继续运行；若规则已被接受则下一次真实公仓领取受到约束。

不人为保证上述活动会按分钟触发；它们是用来评估世界能否自然产出可玩的**测试情境**。

## 简洁交互：三种入口

### 入口 A：右键居民

默认先显示必要信息：**正在做什么、为什么、遇到了什么困难**。展开后可以选择：给予真实物资、提议合作、分享自己知道的资源点、询问他掌握的知识、表达意见。仅当角色、距离、权限与物资可行时出现具体选项。

一个最小 UI 例子：
> 伊洛：正计划采集浆果。原因：自己饥饿、公仓库存不足、知道东边有果树。困难：路途较远。  
> 选项：提供食物 / 告知已标记地点 / 提议同行 / 暂不打扰。

重要：居民应具备拒绝能力。例如即使得到玩家提示，也可以因照料责任、危险或缺时间而不前往。

### 入口 B：右键设施

公仓、火塘、工作点与施工场地复用 Minecraft 交互。向公仓贡献食物必须真实移动物品；建设需要真实材料与施工。避免冗长搬运小游戏，但不可直接创建虚构产品。

### 入口 C：营地公共事务

仅当有真实问题与提案时显示议事入口，不预设每七天开会。玩家能了解原因、支持方案、提供材料、提议调整；居民是否采纳取决于关系、立场、知情程度和规则执行成本。界面不应是“选择制度名称=立即升级社会”。

## NPC 决策：统一但有边界

```text
感知(本人的生存、社交、任务和已知环境)
  -> 构造可行行动（权限、距离、时间、工具、物资）
  -> 按需求紧迫、任务收益、风险、协作、规范与个人偏好排序
  -> 保持短期计划（不每 tick 重新规划）
  -> Minecraft实体执行或有限抽象结算
  -> 单一库存提交、事件账本、关系/记忆更新
  -> 重要条件变化时再规划
```

- 不让NPC直接读取未获知的远程资源或别人的全部私有库存。
- 停在原地时显示“缺工具 / 找不到路 / 资源耗尽 / 等待其他人的决定”等真实原因；区分程序卡顿与模拟等待。
- AI可以使用有限随机扰动，但需保留触发行动的主要因果理由。
- 优先扩展现有 `VillagerWorkGoal` / 模拟核心，不创建第二个独立的无限循环 AI。

## 第一个可交付切片：P-Interaction-01

**玩家帮助一位有生存需求的真实村民，影响后续实际行为。**

1. 右键村民看到需求、当前任务与其形成原因。
2. 玩家选择交付一定真实食物；服务端校验、转移库存并写入事件账本。
3. 村民根据自身状态和规则接受或拒绝，不强迫 NPC 每次服从。
4. 成功行为影响饥饿、事件记忆及与玩家的关系，存档重进后依旧存在。
5. 后续求助、互助或公共讨论至少有一个分支依据本次经历出现可验证的差异。

### 最小事件记录

```text
InteractionEvent {
  initiatorId, recipientId,
  requestType, context, offeredBatchIds,
  action, refusalReason?, result,
  inventoryTransfers, memoryEffect,
  ledgerEventIds, tickOrSimDay
}
```

不必新建全套结构，优先复用已有事件账本及居民映射对象。玩家与 NPC 处于相同的物资/权利约束，而不具有无限执行权限。

### 验收（Fabric GameTest + 体验测试）

- [ ] 食物交付前后库存守恒、物资批次不重复，拒绝时不扣物品。
- [ ] 同一玩家对不同情境的两个村民施以相同帮助，可以得到不同的合理结果。
- [ ] 重要经历影响后续至少一次实际行动，非仅UI好感值。
- [ ] 服务端保存后重载不丢失、不同客户端状态一致。
- [ ] 无玩家时 NPC 仍按原有行为自主工作。
- [ ] 异常断线、满仓、远距离请求、重复点击和错误权限不会复制或丢失物资。
- [ ] 右键解释能明确区分模拟决策、寻路失败和等待材料。

## 后续增强（不阻塞本切片）

- P-Interaction-02：玩家向 NPC 传授知识、协同生产与技能验证。
- P-Institution-01：玩家参与真实公仓协商，新规则实际改变领取，不要求全员同意。
- P-Settlement-01：玩家和 NPC 共同决定一次设施扩建，建造与维持占用真实劳动。
- P-History-01：长期返回营地时看到原来行动带来的可核对历史痕迹。

## 设计边界

- 不因帮助NPC就自动获得政治支持。
- 不因多数居民行为相同就自动认为规范已成立。
- 不因有人具有首领头衔就自动赋予生产资料所有权。
- 不按固定时钟触发粮食危机或对话剧情。
- 暂不引入现代商店、工资、金币或自动社会升级。
- 不强制加载整个世界；远处聚落必须有严格计算边界。
