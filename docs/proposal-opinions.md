# 提案利益方向与居民个性

## 玩家能看到什么

开启既有 survival 与 norms 后，居民面对公仓分配提案，先比较它与**当前有效规则**的变化，再结合饥饿、互助、余粮、信任和已保存的自利倾向形成当前意见。普通右键/居民窗口的提案询问与实际手动、自动会议共用计算。询问不会投票或改变历史；真正讨论时才更新参加者立场。

例：没有有效基础配额规范时，实际默认是每天3件。提议2件是削减，3件没有额度变化，4件是增加。饥饿不再无条件为这三种提议都加支持分。照护额外份额只改变 needsCare 居民的额度，普通成年人的自身饥饿不再被算成照护提案的直接收益；其家庭受照护者及互助关系仍可影响意见。

这是有限的游戏偏好模型，不是人格决定立场、现实政治分类或完整制度模拟。提案额度是领取上限，不保证有食物可领，也不是当次实际消耗量。

## 当前评分边界

只改变带明确默认配额的实际聚落适配路径。两参数独立模拟器的旧公式保留，既有纯Java对照实验不会被悄悄换规则。默认基分35，55及以上支持、40以下反对，其间未决定；会议参与、信息、监督、轮次与通过门槛不变。

- NEED：比较提议基础额度与 ACTIVE 基础规范，缺少有效规范时用3。原照护加额不变。
- CARE：比较提议加额与 ACTIVE 照护规范，缺少有效规范时用0，且只影响 needsCare。基础额度不变。
- DORMANT 的历史数值不是现行待遇；恢复相同历史数值也可能改变实际额度。
- 本轮使用增减方向，不按多增/多减几件线性放大分数。
- 只统计同营地存活居民；家庭可含本人，保留本人饥饿与家庭饥饿两个不同权重。

| 考量 | 本轮权重 |
| --- | --- |
| 认可邻里互助，且同营有受影响的饥饿者 | 增额 +15，减额 −15 |
| 本人饥饿且额度受影响 | 增额 +15，减额 −15 |
| 同营家庭有受影响的饥饿者（含本人） | 增额 +10，减额 −10 |
| 已有不满，家庭额度受影响 | 按方向最多 ±15 |
| 对提案者的既有信任 | 信任值 ×0.15，与额度方向独立 |
| 家庭营养储备严格超过三日需求且家庭受影响 | 增额 −20，减额 +20 |
| 公仓营养储备不足全营三日需求且有受益对象 | 增额 −10，减额 +10 |

额度不变时，所有额度方向项归零；已有信任仍保留。储备比较使用营养点，不混淆鱼、块茎的物品件数。不满项只是对相关家庭额度偏好的有限近似，不声称已经识别不满的真实原因；营地压力也不代表确定耗粮。不同情境可能抵消，因此不保证某类提案被通过。

## 人格从哪里来

成员原已持久化的 selfishness（自利倾向0–100）继续作为本人/家庭饥饿利益的权重：50为中性，原始修正最多提高/降低20%、最多±5。高自利更强调相关饥饿利益，增额时正修正、削减时负修正；低值减弱该利益的权重，并不自动反对增加。没有相关饥饿利益时该项为0。

第八十五增量只追加已保存的 GENEROUS（慷慨）特质：居民已经认可 neighbor-requests 互助惯例，且同营有**存活、非本家庭、饥饿且额度受影响**的居民时，原始修正为增额+3、减额−3。CARE还要求该他家居民 needsCare；同额、只有自家需求、无适格者都不触发。不按人数放大，不自动学习互助惯例，也不改信任或社会关系。这里是游戏模型当前需求，不代表居民已经听过某位邻居的具体请求。

两项人格贡献的**绝对值之和最多5**。若原始自利与慷慨的绝对值之和超过5，两者按同一比例缩小，保留各自方向；相反贡献可以抵消。例如原始+5与+3会显示+3.125与+1.875，而不是叠到+8。没有慷慨作用时，上轮自利值完全不变。

GREEDY对自身食物利益的作用与自利数值重复，本轮不再叠加。诚实、雄心、外貌、战力等也没有当前分配提案所需的对应事实，不硬绑票型。慷慨不会保证支持所有提案，自家饥饿、储备压力、信任和具体增减仍有分量。

权威来源仍是 Members.Personality，没有第二份人格存档。新建和重载模拟均绑定当前成员；移除或异属成员、未映射的人物、独立模拟/非权威营地使用中性值。旧档缺少人格时沿用原成员加载规则，不新增迁移，不覆盖自定义保存值。

询问中的因子名称不再写死正负号，而是显示当次贡献的真实方向；列出最多三个主要因素，并补充尚未入前三的非零自利/慷慨贡献，总计最多五项；显示的是缩放后的实际方向。只显示当前倾向，不承诺下一次讨论结果。

## 历史、资源与验收

- 不重写旧提案额度、已存立场、通过/拒绝结果、规范修订或历史事件。旧开放提案仍保留原额度，但下一次实际讨论会按当时有效规则重新评价。
- 不创造或搬运食物，不清领取账本，不新增NBT字段或改变根版本。通过规范后的实际领取仍用原执行路径。
- 自动回归覆盖有效/休眠规则、增减/同额、照护本人/家庭/外人、营养储备、组合人格预算、他家需求门槛、真实会议公式一致、查询纯度及已保存数值/特质重载。旧支持夹具改为真正增额；历史2件提案仍保存，但饥饿居民可在新讨论中拒绝削减。
- 未启动Minecraft、服务器或GameTest。实际居民UI、自然现场协商和长期人口分配平衡仍需实机验收；GameTest仅同步场景前提与源码编译，不把它算作运行通过。
