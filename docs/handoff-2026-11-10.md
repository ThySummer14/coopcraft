1. 退出客户端、正常停服并等保存结束，复制整个世界及实例配置、mods清单；保留未升级原件。旧根存档版本仍是24，不表示新用途货物向下兼容。

3. 在该实例的实际 `mods/` 中移走旧 CoopCraft jar，放入新jar；不要留下改名的旧包或双份API。多人两端使用同一构建。
4. 专服也只对副本操作；初次安装可在独立仓库副本的 `server/` 执行 `./setup.sh /path/to/coopcraft-0.1.0.jar`，运行Java 21，由用户本人阅读并同意EULA后 `./start.sh`。详细步骤见 [服务端说明](../server/README.md)。客户端附加音乐模组不装到服务端。

6. 下列测试均由用户实际执行。发现重复物品、丢物或持续卡死，先停在测试副本，保留日志与复现步骤，不继续覆盖原世界。

## 第一阶段：默认实物模式、仓台与工具

- 先建平坦、已加载测试区，钟32格内至少两名存活且未归属别营的村民；不潜行右击钟建营。查询 `/coop settlement status` 确认状态，不自动开启模拟开关。
- 钟48格内潜行右击箱子/木桶登记公仓，潜行右击工作台登记制作站。仓台旁留同高、坚实、安全且空头顶的水平邻格及通路；给居民普通食物。
- **先测领镐：** 公仓放一把全新、无命名/附魔/损伤/用途标记的普通石镐。空主手、包内及副手均无镐的成年居民应实际到仓取走同一把；不消耗圆石/木棍、不产生制作经验。已有私人镐者不被替换，多人争同一把不能复制。
- **再测制镐：** 单独准备缺镐居民，公仓不放成品镐，放3普通圆石+2普通木棍；观察领整批、走到台前制作、实际装备1把。最后一批材料取空后仍能完成；不足整批时不得先扣部分。公仓成品领取本身不要求工作台。
- **再测建材：** 保留住房缺口，观察木板、门、白床、线织白羊毛、火把的仓→台→仓过程。配方分别是1橡木→4木板、6木板→3门、3白羊毛+3木板→1白床、4线→1白羊毛、1煤或木炭+1木棍→4火把；没有需求不保证开工。
- 用 `/coop settlement materials`、`/coop settlement construction`、`/coop settlement construction sites` 看缺料/暂停/选址原因；普通右击居民或钟看动作。登记现有床用主手空手潜行右击完整床，不等于保证寻路或繁殖。
- 分别在领料后挡路、装满仓、改变仓台登记、占用主手；应保留实际货物且不补造。解除阻挡观察返仓，部分接收只扣实际量；随后正常退出重进，核对物品余量与旧任务没有被凭空续做。

## 第二阶段：许可、农田、剪毛与返仓

- 先保护建筑：`/coop protect start "测试保护区"`，主手空手潜行右击两个地面角点，`/coop protect confirm`；用 `/coop protect list` 查看。保护覆盖整高度，不保护原版农民、踩踏、机器或所有间接变化。
- 木石先用小范围：OP2站中心执行 `/coop settlement gathering preview wood 4`，核对范围后 `/coop settlement gathering confirm`；撤销用 `/coop settlement gathering revoke`。`stone`/`both`同样支持，半径1–8，包含玩家放置的材料；UNKNOWN观察不是天然来源或采集授权。
- **单独测主动勘察：** 在营地附近布置同高平坦、3×3净空且坚实的通路，将木石许可区放在居民最初12格之外但仍在合法营地范围内（例如距钟40格，半径4），区内中心放普通橡木原木。保持沿途及寻路搜索区已加载，并让健康、不饿、无待返仓货物且有伐木分工或实际木料需求的成人空闲。应能看到“勘察许可材料区”、分段前进与短暂停留；新观察出现后才按原采集选择，不能直接凭勘察获得木料。
- 分别在途中撤销许可、同范围重授、给许可区任一角加保护、制造狭道/高差或让区块不再活动，确认旧勘察停止、不改地形、不凭空产物。恢复条件后须重新选择；旧票不跨退出重进续用。每趟最多600tick/12次寻路，到达等待最多120tick，停止退避400tick。
- 勘察只支持保守平地短程：不绕障、不上下坡、不进入矿道，也不保证遍历许可区。多居民共享原观察器，120tick未必轮到该居民；每营64条/每维1024条观察满额也会暂停，不删除抑制记录。没有线索不表示区域采空；原版Brain、门行为和大量居民同时出发仍须实测。
- 浆果另需 `/coop settlement foraging preview 8` 与 `/coop settlement foraging confirm`，撤销用 `/coop settlement foraging revoke`。保护始终优先；用普通玩家核对许可写命令被拒，查询可用。
- 土豆人工采收：主手空手潜行右击已种土豆切换标记，成熟后应留1颗复种、保留净掉落与副产物。扩种只在默认实物模式用 `/coop settlement planting mark <x> <y> <z>` 明确授权现成空耕地上方作物格；OP2须实际在6格内，撤销用同前缀 `revoke <x> <y> <z>`。撤销扩种许可不取消独立人工标记。
- 剪毛：`/coop settlement shearing nearby` 取得实际羊UUID，OP2用 `/coop settlement shearing preview <羊UUID>`、`/coop settlement shearing confirm`；撤销为 `/coop settlement shearing revoke <羊UUID>`。准备缺白床羊毛需求、获准白羊及公仓剪刀，观察空手居民借用、实际剪毛、羊毛与剩余剪刀返仓。
- 途中新加保护、撤销许可、满仓/断路后均检查不越权、不丢余量、不重复入账。许可不证明羊的所有权，也不授权杀羊、繁殖或后代。死亡剪刀清算需现场证据，按 [清算文档](dead-shears-reclaim.md) 单独测试。

## 第三阶段：可选模拟与社会机制

仅用户明确要测时，在另一份副本开启。命令面向实际玩家所在维度、最近64格内聚落，写开关需OP2；不建议一开始全部开启。

```text
/coop settlement simulation survival true
/coop settlement simulation production true
/coop settlement import tubers 64
/coop settlement rations
/coop settlement events 5
```

- 先在公仓放足普通马铃薯，再执行import并核对实际数量；开启survival不会自动导入原有箱内食物。持续补粮，不能把请求64当作实际成功64。
- 此模式新采浆果/土豆先成为带年龄实物，实际返仓才转为公共模拟粮；鲜货也不能直接原版食用/喂养/种植/烹饪。满仓、跨日、保存重载应保龄不复制，详见 [命令与食物边界](settlement-commands.md)。
- 需要技能/制度实验时再逐项 `/coop settlement simulation skills true`、`/coop settlement simulation norms true`；`growth true`另行选择，不保证出生。自主协商还要单独 `/coop settlement meeting autonomy on`，旧档默认关闭。
- `/coop settlement simulation survival false` 会关闭其余四项但保留抽象库存；必要时显式export，不视作一键还原。食物、工时、提案和会议细则见对应文档。

## 实现范围与后续优先级

- 已接入名册/居民界面、人格与部落首领、公共住宅、明确资源许可、指定农田与剪毛、部分实体加工运输、幼儿送食及现场社会互动。不是完整文明模拟，也未承诺所有增量在真实世界都能顺畅运行。
- 第一优先级：完成上述实机数量、导航、原版Brain并发与重载验收，用提交+复现步骤+前后物品数+脱敏日志记录问题；先解决阻塞，再扩功能。
- 有界许可区勘察已实现：被动观察仍为8格，采集目标仍限12格，未扩大扫描或授权。后续先根据实测评估保守直线/同高度路径与多居民轮转问题；不能把观察当成天然来源证明。当前没有全营勘察并发上限，许可区任一部分与保护区相交会保守暂停整趟。
- 烹饪需独立设计并明确授权灶台/输入使用，证明原版熟食输出来源与真实扣料，再接食物适配器；不能直接把熟食算新鲜公粮或绕过带年龄货物隔离。
- 私人装备、公仓高级工具与借还/死亡全生命周期尚未全面完成；木棍、磨制、营火及部分施工仍有旧远程路径，尚无全营在途预约或完整物流调度。
- 保守保留未知货物不等于任意第三方模组、实体转化、资产生命周期或跨文件崩溃都受保证；不得据局部测试宣称全局守恒。
