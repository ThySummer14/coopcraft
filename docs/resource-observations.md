# 居民资源观察：安全第一步

居民会自行记住曾观察到的成熟甜浆果、橡木原木、石头/圆石候选。这是独立的观察记录，本身不会新增采摘或破坏权限。实际甜浆果采摘现由单独的[安全觅食许可区](safe-foraging.md)约束；木石自动采收另须独立的[材料许可区](safe-material-gathering.md)，原人工标记保留。

## 能做什么

- 服务器自动轮转已登记居民，在当前维度、聚落中心 64 格内，观察居民周围水平半径 8 格、上下 2 格的范围。
- 登记成熟甜浆果（年龄至少2，`SWEET_BERRY`）、普通橡木原木（`OAK_LOG`）及石头/圆石（共用 `STONE`）。首版不扩到其他树种、去皮木、木板、深板岩或矿石。来源始终为 `UNKNOWN`，玩家放置的同款方块也不例外；树叶、外观、群系或远离建筑均不能证明天然来源。
- 记录所在维度由当前维度的 `SettlementSavedData` 确定，并保存聚落 ID、坐标、种类、未知来源和候选/抑制状态。
- 候选表示**曾观察到**，不保证当前方块、成熟度、可达性或采收权。没有视线、路径、天然来源或土地所有权判断。再次看到另一受支持种类时原位更新普通候选；看到不支持方块时移除普通候选。抑制按坐标保持，不因材料替换而解除。未再次扫描时仍可能保留历史记录。
- 观察没有派工、任务预约、寻路、掉落计算、采收、物品插入或模拟批次生产。它与当次生产任务票完全分开。

## 查看与管理

| 命令 | 权限 | 含义 |
| --- | --- | --- |
| `/coop settlement observations` | 普通玩家 | 只读查看候选/抑制数量，以及记录 ID、位置、材料种类、状态和当前保护否决 |
| `/coop settlement observations suppress <ID>` | OP 2 | 将已有候选原位改成持久抑制，重扫不恢复候选 |
| `/coop settlement observations resume <ID>` | OP 2 | 显式移除抑制并释放额度；需要重新观察，才会出现新候选 |
| `/coop settlement status` | 普通玩家 | 增加历史候选数量和查看命令提示 |

命令仍选择玩家实际所在维度、距离 64 格内最近的已登记聚落。ID 来自查看命令，不接收任意坐标或采收授权。抑制作用于所选聚落的观察，并使依赖该候选的新自动木石任务失效；它不撤销区域许可，不影响原人工标记或甜浆果采摘，也不是跨聚落禁采区。其他聚落的独立观察不受影响。

每聚落的候选与抑制**共用 64 条**额度，每维度共用 **1024 条**。满额时不添加新候选，不淘汰任何抑制。抑制已有候选不需要额外空间，因此满额取消也不会下次立刻复活。可以用 `resume` 纠正误操作或释放抑制额度，但同坐标仍有受支持资源时，后续重扫可重新记录并占用额度。当前没有自动淘汰或“清空全部”操作。

## 权限与旧功能边界

`ResourceObservations` 和人工授权 `ResourceSites` 是两个独立存档字段。发现器不调用 `toggleResource`、不把坐标写入人工资源标记。即使后来观察到橡木原木、石头或圆石，或浆果被换成这些材料，也不会因此进入已授权采集列表。木石自动采收必须另有本营明确材料许可并重新核对当前候选与现场；原人工木石、土豆仍沿原标记权限。

**自动浆果采摘现在必须位于本营显式许可区，保护区优先否决；旧档没有许可时暂停。** 许可包括区内玩家种植的浆果，所以应谨慎圈定。甜浆果实时采收不以历史候选数量或状态赋权。木石自动路径额外要求当前未抑制候选存在，抑制会停止此候选的自动木石任务；仍不能代替保护区或撤销许可。人工木石与土豆标记、撤销语义保持不变。

明确材料许可区内的自动木石采收已单独实现，详见[安全木石采集](safe-material-gathering.md)。许可、当前匹配方块、执行前复核及瞬时预约共同约束实际采收，未知来源观察不能代替任何权限。

## 成本与资格

每维度仅一个扫描器，每游戏 tick 最多选择 4 条成员记录、尝试 16 个坐标。越界、未加载及被抑制坐标同样消耗本轮坐标预算；不在一个 tick 内跳过大量无效位置寻找有效目标。固定扫描盒共 1445 个坐标，静止有效居民的一轮最多约 91 tick；多人按成员轮转，实际重访间隔受居民数量、有效性和移动影响。

- 必须是当前仍属于唯一聚落的活成年村民，未被移除、未睡眠、未 NoAI，处在正确维度，且自身已加载、entity-ticking、在聚落范围和世界边界内。
- 跨维成员核验每 tick 创建有界快照，最多读取 32 个维度的原始成员表；超过 32 个、来源缺失/重复、孤立成员或跨维重复归属均保守停止相关观察。它不调用每坐标全聚落搜索。
- 原始成员查询为 O(1)，每个 tick 最多缓存 4 名候选居民的唯一归属结果；每次读前和读后复核各来源的成员代次。取消、重新登记或新增外维 claim 会使本 tick 的缓存失效，不能复用旧身份。
- 成员轮转队列为瞬时 O(1) 数据结构，随登记/移除同步。无关成员变动不重置有效观察者的当前扫描进度，也不会始终从第一名居民重新开始。
- 每个目标在读取方块前检查距离、建造高度、世界边界、保护区、已加载和 entity-ticking；读后再次核验保护。保护数据损坏时也拒绝目标读取，不靠空保护恢复扫描。没有强加载。扫不到目标不代表目标不存在。
- 三种资源共用原扫描进度、16坐标预算和64/1024记录上限，不为每种材料另扫一遍。保护区内不新增观察；已有历史候选和抑制保留，查询标明“受保护或保护数据不可用”。没有保护否决仅表示此层未阻止，绝不是采收授权。
- 同一 tick 重复调用不追加预算。同一候选重扫不刷新时间戳、不反复标脏，仅候选新增/失效和用户抑制/恢复时标脏。

## 存档

观察在根 `DataVersion` 20引入（当前根版本23），字段 `ResourceObservations` 当前独立 `Version = 2`。合法版本1的旧浆果候选、抑制和 berry-ID 保留，保存时升级为版本2；旧版本1内出现木石等原本未知种类仍整块保全，不能借升级重新解释坏档。旧档无字段时为空，不从人工标记推导任何候选或来源。

未知子树版本、未知字段/类型/来源/状态、缺字段、错误 NBT 类型、重复坐标和超限记录均使**整个观察子树原样保留并暂停该子树的观察与修改**，而不是部分解读、默认授权或静默清空。查看命令会说明数据未知/损坏；其他已有系统继续按旧逻辑运行。该保全保证针对新增观察子树，不扩展为对整个历史存档格式的全面修复。

普通候选种类改变后记录ID随种类变化，旧ID不能修改新种类记录；抑制仍保留原种类和ID，直到显式resume。

扫描进度、轮转顺序、成员代次和跨维快照不存盘。重启后重新开始扫描，但抑制持久保存。聚落 ID 索引只从已有中心表的最终记录建立；同中心被覆盖的旧记录不能残留在新索引，同 ID 多中心时新观察资格保守不可用，不擅自修复原始成员归属。

## 验证范围

新增 JUnit 直接执行生产扫描器 Probe、真实 `SettlementSavedData` 序列化、真实方块状态和容器；覆盖预算、资格、跨维冲突、名册活性、重复/损坏数据保全、容量、抑制恢复、未知来源、方块替换不授权与外部状态不变。命令测试执行真实 Brigadier 语法和只读投影；tick 的 AST 测试仅检查生产接线结构。

以上是自动化测试的设计覆盖，是否运行通过以本次 CI 结果为准。未运行客户端、服务器或 GameTest，不能据此称为实机观察、寻路或采收验证。
