# M1a：安全试掘与真实返仓编码规格 v0.1

> 日期：2026-11-09；性质：待实现规格，不是已通过的矿井功能。
> 关联：[矿业研究](../构想/09-矿业生产与技术传播-2026-11-09.md)、[研究PR #42](https://github.com/ThySummer14/coopcraft/pull/42)。

## 1. 冻结一个小目标

**居民从安全地表入口向实心岩壁挖一条短探巷，挖一块、携带真实产物、实际回仓，再继续下一块。**

本切片选择“单步采掘与风险边界”，不继续扩展整套社会史。

| 本次规格内 | 后续切片 |
|---|---|
| 一个明确批准的入口、有限采掘体、一个工人、水平短探巷 | 自动选址、下行阶梯、分支矿井、深井 |
| 石头/圆石/煤矿石，按真实镐与掉落执行 | 铜铁冶炼、完整矿种、地质世界生成 |
| 只读风险检查、单步授权、工时、实物返仓 | 自动支护/铺轨/安装灯具、机器 |
| 报告记录真实矿样，成功或无矿都可结束 | 地质天赋评分与跨聚落报告传播 |
| 沿现有共同材料规则搬运 | 新产权、雇佣、劳役与交易 |

水平探巷从实心岩壁开出，不要求天然洞穴；它只是总方案M1的第一个增量，不能被宣称已经实现从任意平地向下开矿。初期入口、照明和已有回仓路线由测试夹具或玩家正常建造提供；不会隔空取公仓材料建井。

## 3. 最小数据和状态机

### 3.1 项目记录

建议只保存一份 `MineProject`，字段如下。类型名供代码评审调整，不要求为每行新建独立类。

| 字段 | 含义 |
|---|---|
| `id, settlementId, dimension` | 稳定项目、聚落和维度身份 |
| `revision, enabled` | 当前授权版本；取消/改范围/换入口立即增加版本并停旧动作 |
| `origin, forward, right, length` | 水平入口局部坐标；首版长度1–4格 |
| `excavationBounds, protectedMask` | 有限允许体与明确禁挖格，最终逐步检查 |
| `knownEntryAir, completedPrefix` | 现场登记的入口空气与已完成断面的可行走通道，不从任意地下空气扩展 |
| `verifiedClearedCells` | 本项目逐格成功清理或重新安全核验的空位；最多16格，未完成断面也可登记，但不因此允许站入 |
| `targetSnapshot` | 当前已暴露下一目标的状态、工具与观察版本；不预读整条未暴露矿体 |
| `nextOrdinal, completedCount` | 下一格及已成功处理格；计数不能推导物品库存 |
| `status, blocker, lastObservation` | 项目状态、具体阻碍及最后实际观察 |
| `lootPolicyRevision` | 当前支持的掉落/工具规则；资源重载后停工重验 |
| `deliveryPhase, deliveryReceipt` | 本步携货/实交/遗物移交/异常结果与真实交付服务回执；只是审计信息，不可消费或交易 |

项目不保存“矿石总库存”“即将到账资源”或物品所有权副本。待提交掉落计划只是未发生结果的模板，不参与容器计数、配方、交易或物资守恒总量。

### 3.2 状态转移

| 状态 | 进入动作 | 可走向 |
|---|---|---|
| `SURVEY_PENDING` | 到已批准入口，只读检查地形与回仓前提 | `READY` / `PAUSED` |
| `READY` | 选择既定顺序的下一格，取得唯一工作占用 | `APPROACH` / `COMPLETED` / `PAUSED` |
| `APPROACH` | 沿已知前缀到上一完整断面的站位 | `WORKING` / `PAUSED` |
| `WORKING` | 每tick复核资格与站位，累加实际劳动 | `COMMITTING` / `PAUSED` |
| `COMMITTING` | 同一服务端调用中最终复核并执行一次世界变化 | `RETURNING` / `READY` / `PAUSED` / `NEEDS_REVIEW` |
| `RETURNING` | 现有材料返仓动作负责搬运；本步矿物在途时禁用会消耗它的加工动作 | 本步真实交付回执确认后 `READY`；满仓等保持阻碍；其他去向分别记为暂停/遗物保全 |
| `PAUSED` | 不挖、不增工时；保留项目、真实货物及暂停前阶段 | 原因解除后重验，未实交的一步回`RETURNING`；无待处理结果才回`READY`，或`CANCELLED` |
| `NEEDS_REVIEW` | 世界可能已变、结果不确定 | 不自动重放；只读显示事实，交由显式恢复流程 |
| `COMPLETED` / `CANCELLED` | 停止新挖掘，已形成的通道与货物保留 | 若重新立项，重新验证，不复用旧票据 |

`COMMITTING`不是可跨tick悬挂的授权。瞬时工作票据绑定项目版本、成员身份、实体实例、目标、手持工具身份/状态和当前作业占用；`stop`、卸载、死亡或改属均释放占用。正常重载从实际世界及背包重建任务，不能恢复“已获许可，无需重验”。

急迫进食与危险回撤优先于开新工作。`PAUSED`必须返回既有需求/其他劳动调度，不能占住Goal导致永不吃饭。取消矿井不取消携带者把既有材料送往当前合法公仓的能力。

## 4. 可直接编写夹具的几何

### 4.1 局部坐标

入口左列脚部空气格定义为 `O`，水平朝向为 `F`，右向为 `R`。第 `i` 个断面，`i=1..L`，待挖位置为：

`O + i*F + j*R + k*UP`，其中 `j∈{0,1}`、`k∈{0,1}`、`1≤L≤4`。

- 初始可站位为`O`和`O+R`，两列脚部、头部与脚下支撑分别验收；`knownEntryAir`仅登记此入口及有限退路的现场空气，不无限扩张。
- 共2格宽、2格高、最多16个目标方块，全部同一地面高度；不挖其下方支撑。
- 每断面固定顺序：左上、左下、右上、右下。下一断面开始前，本断面四格都须成为已验证的安全通道。
- 执行时只能站在已登记入口或前一个完整断面，脚/头是可通行空气、脚下是安全支撑，且真实射线首先命中当前目标；眼睛到目标中心距离不超过2.5格；这是待测候选上限，不覆盖隔墙射线检查。
- 每格确定清理后先加入`verifiedClearedCells`，供后续风险门识别本项目产生的空气；只有断面四格全已清理且通道安全，才扩展可站立的`completedPrefix`。两者不能混用，否则第一格形成的空气会把第二格误判成未知洞穴。
- 原目标已被玩家挖成空气时不发物、不耗镐、不记采掘技能。对该空位及其暴露邻域重新进行有限安全检查，通过后逐格登记为外部已清理并推进序号；四格完成前仍不许站入。未通过则暂停，不假定玩家移走的物品属于聚落。
- 发现目标与本次快照不同、可信空位或完整前缀被填回、容器或功能方块介入时暂停。M1a不自动“修复”通道。玩家在项目内放置的方块须由保护记录排除；仅比较`BlockState`无法识别同种方块移走后又放回，不能宣称完整玩家建筑溯源。配置无法追踪的世界修改来源时，保守停用自动试掘。
- 所有工作位置继续满足现有聚落活动范围；本切片不扩大64格三维资格。深井资格留给后续M1b独立设计。

### 4.2 白名单

待挖方块仅 `minecraft:stone`、`minecraft:cobblestone`、`minecraft:coal_ore`；不得因 `mineable/pickaxe` 标签就认为任意方块可自动破坏。方块实体、流体、含水方块、负硬度、功能块及非白名单方块均拒绝。

工具为经实际1.21.1代码核对的原版镐，并按原版工具适用性与正确采集等级判断。附魔/组件不删改；不支持的工具回调明确阻塞，不能悄悄换成徒手。磨制石镐的效率/耐久行为需在受控服务测试中覆盖。掉落由实际方块、实际工具快照和服务端规则计算，不手写“煤矿固定给煤”。

M1a支持的货物输出至少覆盖上述方块的普通及精准采集结果：圆石、石头、煤、煤矿石。首版只支持经审阅的上述原版掉落表、标准工具条件和固定上下文；活跃掉落表或引用链被数据包改写而未登记为支持时，整步暂停。不能仅凭输出物品在白名单就放行动态条件。数据包/附魔若额外产生未接入搬运和死亡保全的物品，同样整步暂停，不先挖再丢弃。命名/组件保留；若需限制特殊物品，要在动作前明确拒绝。

## 5. 破坏前安全检查

### 5.1 检查次序与读边界

1. **身份和许可先行**：服务端、存活成年成员、同维度、唯一归属、有效项目版本、允许体、禁挖区、工时、`mobGriefing`及服务器矿业开关。
2. **范围与加载先行**：按整数溢出安全的方式列出目标、站位/头/脚下、短前缀及目标周围至多3×4×3格邻域（水平两轴各偏移-1..1，竖直偏移-1..2）；先验证高度、世界边界、已加载与entity-ticking，再读取任何状态。未知不等于空气。
3. **目标**：仍是允许且未改变的方块，无方块实体和流体，正确工具与掉落规则可用。
4. **站位**：实体实际站稳于允许格，不在跳跃/跌落中；碰撞与目标射线通过，不能隔墙开采。
5. **邻域**：直接接触流体、含水状态、可能失去支撑的重力方块、未知开口或不支持的更新行为均拒绝该步。
6. **退路**：已登记短通道前缀仍净空、有支撑、无流体/危险，既有回仓目标可验证；不把一次旧寻路成功视为永久退路证明。
7. **权限适配**：服务器已配置的领地/保护适配器允许该NPC动作，才准备最终提交；未知/拒绝不退回直接`destroyBlock`。

邻域检测是有限安全门，不是完整地质、流体或模组更新证明。初版将异常保持为`hazard_unknown`，不能宣称任何地下条件都安全。风险查询返回“允许/阻塞及原因”，不得把隐藏矿种、数量、坐标传给勘探选点或技能模块。

`knownEntryAir`只覆盖首次实际登记的有限地表入口范围；`verifiedClearedCells`只覆盖成功清理或逐格重新验证过的本项目目标；新的地下空气不自动加入。这样“挖穿最后一层墙进入洞穴”在执行前被阻止，又不会把原有地表入口本身误判成未知洞穴。

### 5.2 两个必须显式解决的边界

- **附近有危险但不在授权体内**：可做加载范围内的有限只读安全检查，不得为了消除危险去挖、填、抽干授权体外方块。
- **保护插件**：Fabric的玩家破坏回调带有玩家参数，不能据此宣称NPC直接破坏会自动获得全部领地保护。无需伪装成管理员或假玩家；应设计明确的NPC动作权限适配，无法确认的环境默认不开放自动试掘。相关API来源见第10节。

## 6. 单块提交协议

### 6.1 准备

- 以 `(dimension, projectId, revision, targetOrdinal)` 标识一次工程步骤，用不可重入占用防止两人同时提交。
- 劳动进度只在实际可工作的tick增加。完成工时后仍需最终检查，不能因为已经花了时间而豁免保护。
- 用实际工具快照生成**一份**完整掉落计划，容量预演和最终交付用同一份，不再调用第二次随机掉落。
- 容量必须包含全部物品及组件；背包副本只是本次插入计划，不能成为跨tick权威库存。
- 满包、短暂暂停、正常重载和重新立项不能重抽收益。首版选择固定上下文＋局部稳定随机方案：以世界内部种子、维度、目标位置、方块状态、影响掉落的工具属性和经审核掉落策略内容指纹形成输入；不得使用项目ID、创建时间或可随重试改变的版本计数，也不扰动世界全局随机源。工具耐久等不影响掉落的状态不得提供额外抽奖机会。
- 相同输入在正常重载、项目取消后重建及满包重试中保持相同结果。换镐附魔会按新工具重新核验并使用对应固定结果；资源重载先撤销票据，同内容指纹保留相同结果，内容变化且未审核则停工。依赖时间、天气、其他实体或任意动态谓词的自定义掉落不进入M1a支持范围；稳定随机种子不能冻结这类条件。
- 实际1.21.1掉落调用、局部随机注入和活动掉落表识别接口在编码时静态核验；无法保证时缩小为已经能核验的确定掉落子集，不以“看上去是原版物品”代替兼容证明。
- 资源重载、目标/工具或权限改变会令准备票据失效；旧掉落计划永远不能在不同目标上发货。

### 6.2 最终执行顺序

1. 在服务端线程消耗一次性提交票据，再重验身份、项目版本、范围、站位、目标状态、工具、邻域、当前容量、保护适配、矿业开关、`mobGriefing`和掉落策略内容指纹。
2. 让世界仅完成一次**不自动生成物品实体**的方块移除，正常触发必要的原版世界更新；不得关闭更新来隐藏危险。
3. 若确定移除失败：不交付、不扣工具、不记生产/经验，释放占用并给出原因。
4. 若确定移除成功：将已验证计划提交到原实体背包，使用本次开采的工具执行一次对应损耗；损坏时保留正确的空手/工具损坏结果，不赠送替代工具。
5. 写一次成功步骤和真实采样/技能记录，推进工程序号；物资只存在于实体背包，不同步加公仓或抽象矿物余额。
6. 进入`RETURNING`，由现有返仓行为处理。矿物实到仓后才可成为后续公共配方资源。

M1a不为NPC开采额外生成玩家经验球、成就或自动熔炼结果；这是明确玩法边界，不宣称完全模拟玩家破坏流程。现有技能调用按**一次实际动作**结算，不能每种掉落重复练习。

### 6.3 异常不能装成回滚

上述约定只对已核验的标准同步、非重入容器/工具/方块路径成立。没有跨世界、实体与SavedData文件的崩溃原子性保证。

- 若世界移除结果不确定、回调抛错或发生意外重入，进入`NEEDS_REVIEW`，保留事实诊断并停止该项目；不要按旧计划自动再发一次货。
- 下次看到目标空气，不能据项目未推进就重建矿物；看到真实背包已有货物，也不能据进度落后再扣一块世界方块。
- 正常保存/重载必须验证可恢复；进程在任意字节写入之间崩溃仍是额外工程课题。损失/不确定性应可见，不能以“自动补偿”制造复制漏洞。

## 7. 与返仓、死亡保全的衔接

M1a不增加运输者转交、背篓、矿车或矿口第二仓。采掘者自己带回已绑定公仓，先证明最短闭环。后续通用装卸、货单与运输网络对接[物流研究PR #43](https://github.com/ThySummer14/coopcraft/pull/43)，共用真实转移结果，不另建矿业库存或货单。

1. 开始本步前不得已有未解决材料货物。实际矿物入包后，`SettlementCargo.hasCargo`必须为真；Goal退出采掘并允许原返仓任务接管。返仓中紧急进食/回撤仍优先，但禁止会消费本步材料的制作或加工，不能只依赖现有`hasCargo`采集门，因为当前Goal的若干制作动作排在该门之前。
2. 现有票据只在真实仓库面邻格最终交付。仓库换绑或双箱身份变化使旧票失效，不需要矿井自己缓存箱子容量。
3. 真实交付服务须返回可关联本步的实际接纳结果，并由单一服务记录回执；部分卸货后继续搬运剩余物，只有该步全部实交才进入下一块。回执不增加仓储库存，也不能用于配方支付。当前交付服务仅给总接纳数，若无法把本步材料与其他携货可靠关联，需要先补足结果接口，不能用“背包变空”替代回执。
4. 临时无仓/满仓保留物资并退避；居民仍可满足紧急需求。项目显示对应的真实物流原因。
5. 发生已覆盖的死亡事件时，沿`SettlementCargoRecovery`从实际背包移交，不同时生成矿物掉落实体；后续领取只减少遗物记录。
6. 背包材料因玩家转移、被加工消耗或其他原因消失时，记为`cargo_changed`并暂停；死亡移交记为`preserved_in_relic`，不是`delivered`。正常保存后恢复回执与实际状态，歧义进入核查，不重新生成矿物。
7. 行政移除、闪电转化和跨文件崩溃等旧物流未保证的情形不得在本规格中突然宣称有保障。扩展矿物分类须覆盖交付、保存、死亡领取与旧版本兼容。

## 8. 失败与恢复表

| 原因码候选 | 世界/物资结果 | 何时可恢复 |
|---|---|---|
| `mining_disabled` / `not_authorized` | 无新世界变化，已有货物仍真实存在 | 明确重新启用/授权并换版本 |
| `target_unloaded` / `probe_unloaded` | 不读未知状态、不加载区块 | 正常加载后重新调查 |
| `target_changed` / `protected_target` | 不挖替代方块 | 维护者调整范围或明确重新立项 |
| `tool_missing` / `tool_unsupported` | 不挖、不赠工具 | 合法取得支持的工具 |
| `unsafe_stance` / `blocked_retreat` | 不增加工作进度 | 实际站位与已知路线恢复 |
| `fluid_risk` / `gravity_risk` / `unknown_opening` | 保留隔离壁，不处理范围外危险 | 重新评估，M1a不自动排险 |
| `cargo_full` / `cargo_store_unavailable` | 全部产物保持原处 | 实际容量/仓库/路线可用 |
| `cargo_changed` / `preserved_in_relic` | 已产出货物有其他去向，不能宣称已入仓 | 对照真实容器/遗物和回执核查；不自动补矿 |
| `loot_unsupported` / `policy_changed` | 不移除方块 | 支持范围经过评审后更新 |
| `stale_ticket` / `already_committed` | 重复调用无第二次结果 | 重新选择尚未完成步骤 |
| `commit_uncertain` | 不擅自补发或回滚 | 显式核查实际世界与物资 |

原因去重和退避，不能每tick刷消息或无限寻路。建议初始每聚落一个项目/工人、每20tick至多一次规划、每次只处理有限邻域与短前缀；预算值是待测候选，不是性能达标声明。全服还需共享上限，不能把“每村有限”误当作“全服无上限也安全”。
