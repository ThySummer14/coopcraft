# 成人送食照料幼儿

## 新增的可见闭环

在默认实物食物模式，空闲成人可以拿自己的真实余粮走到附近饥饿幼儿身边，停步照料后消耗1件食物，提高幼儿既有饱食度。可由原有浆果、土豆采收接上这段送食过程，余粮随后仍能按原流程返仓。

幼儿原本就能自行进食；本轮增加成人送食，不接管原版生育、分享或幼儿全部行为。没有推断父母或家庭身份，不限定某一种人格负责照顾，也不新增社会关系、技能经验或核心模拟CARE工时。

## 玩家怎样观察

1. 使用默认实物模式，同营同时有成人和幼儿。只在survival未开启时选择新照料任务，已有survival食物年龄和抽象库存不被转换。
2. 让成人按已有采收流程取得足量普通甜浆果或土豆。扣1件后，其全部既有可食物点数仍须达到原性格留粮目标，至少12点。本轮不新增给粮命令，也不自动到公仓取照料粮。
3. 幼儿需饱食度不高于35、背包没有自己的可用食物；成人饱食度须高于35。双方健康、清醒、可行动、无交易、无战斗或紧急状态，双手空闲且没有其他材料、用途货物或社会预约。
4. 双方在水平12格、上下4格内；幼儿停在安全全方块上，身体两格为空气，旁边有同高安全站位。成人会尝试靠近，在2.5格内并具备视线时，连续40个真实游戏tick后送出1件。居民当前工作可显示“送食照料幼儿”，成功后有现有挥手动作；没有新物品展示或专用喂食动画。
5. 观察成人背包减1件、幼儿饱食度按原食物恢复公式增加。普通浆果和土豆各为1食物点，对应5饱食度，幼儿背包不凭空增加食物。接触不足或失效时不消耗。

这是机会式短程照料，不保证立即发生。自己的进食、邀请、借用工具和既有劳动优先。只有普通余粮且没有其他保管责任时，照料会在新播种或余粮返仓之前尝试；不强停有效的当前工作。找不到合格幼儿或失败后至少退避100tick。

## 取消与实物安全

- 幼儿始终可以开始自己的进食或活动。新任务不会占据幼儿Goal；幼儿进入忙碌状态或离开初始方块格时取消，不持续追逐。格内轻微移动仍需满足实时站位和视线。
- 任一方卸载、死亡、离营、成员对象被替换、模式变化或身体不适，旧任务失效。双方始终要属于同一个权威聚落，模式先开后关也不沿用旧票据。
- 选择、途中、连续计时及最终交付重验条件。中间失去接触、跨过未观测tick或游戏时间倒退即取消；同tick重复调用不多计时间。
- 只扣成人背包中无组件的普通甜浆果或土豆。命名、用途、货龄等组件物品不会被拆掉标记拿来送食；幼儿物品、成人装备和其他槽保持原状。原留粮算法按既有可食物点数统计，不新增库存权威。
- 最终回调之后再次比对双方完整背包和饱食度，所有授权检查通过才扣1件并更新需求。标准同步、非重入容器下按一个服务操作完成；第三方容器监听器重入及保存崩溃可能打断操作，不宣称跨系统崩溃原子事务。

照料不改任何方块或采收许可，不因送食获得拆建权限。路径沿用已加载区域与安全节点检查，并拒绝路径节点踩耕地。原版Brain可能并行改变路线、站位和背包，能否自然连续同场仍需实机观察。

## 协调、性能与旧档

每个维度的SavedData临时协调表最多128对成人与幼儿；每人同时只参与一对，双方400tick超时、释放后100tick冷却。冷却也占固定容量，不通过驱逐已有预约争抢位置。移除成员与实体卸载释放预约，不修改库存。

每次只在成人附近12格水平、上下4格的已加载局部实体中找幼儿，排序后前16名做深度检查。原版局部实体枚举仍随密度增长，并非全流程固定16次操作。无合格余粮不做实体扫描；搜索有100tick退避，单次行走最多200次更新，不强制加载区块。

预约、票据、路线和接触计时不写NBT，重载重新选择，不恢复未完成扣粮。幼儿饱食度沿既有MemberNeeds保存；没有新版本、迁移、食物副本或历史事件。旧档无需开启新开关，满足默认实物模式和现场条件便可尝试，原有survival玩法保持原食物来源。
