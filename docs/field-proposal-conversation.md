# 仓旁提案转述

## 玩家能看到什么

已经在登记公仓旁的两名同营空闲成年人，可以停步、看向彼此，由讲述者转述一条已有分配提案。居民状态显示“转述分配提案”和“听取分配提案”。两人各自接纳后，连续200个共同到场tick才产生结果，正常20TPS约10秒；不会远程通知所有人。

成功后，听者才获得该消息并按原有处境和个性公式形成初始意见。没有推进会议轮次、采纳规则、改变领取额度或预设赞成票。它可为后来真实会议提供知情参与者；实际表决仍走现有流程。

## 发生条件与观察方法

1. 按原流程开启聚落survival与norms映射并准备实际公粮。开启映射不会补粮，本轮不新增开关或命令；skills和仓旁自主会议开关不是前提。关闭自主会议仍允许消息交流，关闭norms或survival才会暂停此机制。
2. 聚落已经通过真实短缺、拒绝与社会观察形成开放提案。至少一名成年人实际持有对应来源信息，另一名尚不知道该消息或提案。没有议题、已经全部知情、来源账本已淘汰或双方缺少既有信任联系时，不会凭空开始。
3. 两名健康、清醒、不饥饿的成年居民或长者已经在公仓安全同高邻格，彼此不同格且能互相看见。首版不召集、不寻路、不传送；继续工作、吃饭、返仓、工具保管和已有社交邀请优先。
4. 保持现场，观察上述工作状态。双方独立逐tick更新，重复调用不多计时间。离开安全站位、导航再次移动、失去视线、受伤、饥饿、交易或接到优先职责会取消，等待与取消均不发消息或扣工时。
5. 成功的“消息传播”事件可在名册事件页和 `/coop settlement events` 查看；详情记录讲述者、听者、提案ID、原始提案事件、收到的置信度及双方各1小时社会工时代价。这些显示来自当时事件，不拿后来票数重新解释当时对话。

当前附近候选采用已加载局部实体列表，深度检查前16名。其他候选可能占位置，密集聚落不保证公平或每个议题立即传到；底层局部实体枚举仍随密度增长。每人失败搜索有独立200实际tick退避，已有邀请无需等此冷却。

## 来源、结果与成本

只能转述讲述者当前持有的NORM_PROPOSAL信息，置信度至少0.5。原提案事件须与提案ID、提议人、日期、额度、修订号以及原始拒绝/短缺因果链一致；未知、未来、缺失、替换或被淘汰的来源不会被补造。

每次只传一条，保留informationId、kind及原sourceEventId，learnedFrom写实际讲述者。收到的置信度沿既有规则乘0.85，例如1.0变0.85；当原值仅0.5时，收到0.425仍是已知历史信息，但不足以作为下一次转述或会议介绍的可靠来源。不会自动提高信任、教会互助观念、共享路线、远方营地报告、粮食安全估计或让旁观者知情。

双方各付1小时既有社会工时，在下次日结体现劳动代价；每个人的总社会工时不能超过6小时。该额度与原有会议、教学等活动共享，不是额外每天6小时，也不另设每天一次的限制。听者已经从其他路径知道提案、议题已结束或双方工时耗尽时，旧会话不能再收费。

## 现场与存档安全

- survival+norms、核心日、世界日、成员、实体、模拟及模式身份全程复核；开关先关后开也不复用旧会话。
- 登记仓位置、绑定身份、实际箱体和双箱伙伴固定，替换、重登或无法安全读取会取消。保护区优先；站位、身体和扩一格视线包围区先核查加载与活动范围。
- 双方同时只能参与一个提案会话，且不能占用教学、会议、照料或真实货物工作。临时表每维度最多128对，活动与冷却身份合计最多256，600tick超时、结束后200tick冷却；容量满时拒绝新任务，不挤掉已有任务。
- 完成时先消费双端预约，然后复核实际现场和一次性核心票据，再记录知识与工时。重新调用、旧票据、被取消的尝试不再次生效。没有物品、方块或仓库扣取。
- 知识、社会工时和事件沿原格式保存；重载不清当天成本。会话、加入状态和计时不写NBT，重载重新判断，不补算离线对话。旧历史不改写，也不把旧泛化消息传播事件伪装成现场对话。

## 验证边界

回归覆盖来源、身份、工时、保存恢复、重入/失效、双端连续计时、排他、冷却、静态Goal接线与历史显示；纯服务回调只证明事务边界，不代表真实实体已现场验收。

首次分支CI核查构建与单测。没有运行Minecraft客户端、服务器或GameTest；自然站位、原版Brain抢导航、多人变化及真实世界保存重启，仍待用户统一测试。它是限定的提案信息交流，并非自由对话、谣言系统或完整舆论模拟。
