# 逐羊剪毛许可与后续实体劳动

## 本步已实现什么

第七十五增量只接通逐羊许可的查看、附近候选、预览确认、撤销和保存。自动剪毛动作尚未启用，不会改羊的剪毛状态、生成羊毛、消耗剪刀或让村民出发。现有4线→1白羊毛→白床的真实运输链不变。

先划清玩家牲畜的使用范围：羊没有可供本模组可靠验证的玩家主人字段，名称、围栏、牵绳、村庄附近或外观不能代表公共所有。初版由OP2管理员明确选择一只羊，许可仅限指定聚落今后的重复剪毛，不授权杀羊、迁移、染色、繁殖、后代或其他羊。它不是动物所有权证明。

## 使用方法

在目标聚落附近操作：

1. `/coop settlement shearing`：查看本营已保存的许可，不扫描或加载羊。
2. `/coop settlement shearing nearby`：查看真实玩家8格内已加载羊的候选信息，最多显示8条。显示候选不产生许可。
3. OP2执行 `/coop settlement shearing preview <sheep_uuid>`：选择附近一只存活成年白羊，查看精确UUID、聚落与用途后确认。已被剪过的白羊也可登记今后的重复剪毛许可。
4. `/coop settlement shearing confirm`：在预览有效期内保存；预览会被单次消费，失败后应重新预览。
5. `/coop settlement shearing cancel`：取消自己的未确认预览。
6. `/coop settlement shearing revoke <sheep_uuid>`：撤销本营对应许可。羊已卸载、死亡、走远或进入保护区也不妨碍撤销。

只读查询不需要管理员权限，修改需要OP2和真实在线、存活、非旁观玩家。以实际玩家的位置与维度为准，不能用`/execute positioned`远程授权，也不接受跨维度执行。每只羊在同一维度最多属于一营许可，每营16只、每维度128只；换营必须先撤销原营许可，再重新预览确认。

## 安全与存档

- 预览和确认都重新取当前已加载羊，确认必须仍是同一实体实例；UUID相同但卸载重载、死亡后替换等不续用旧预览。
- 羊需在玩家8格内、营中心水平64格内和世界边界内，当前区块必须已加载且活动。不会为确认去加载区块。
- 按羊当前包围盒整个XZ投影检查玩家保护区，边缘相交也拒绝登记；未知或损坏的保护资料同样拒绝。羊移动后重新检查，不能用预览时的旧坐标代替。已保存许可不会因羊暂时进入保护区静默删除。
- 预览绑定玩家会话、实际维度、聚落和存储实例及许可变化代次；其他管理员改动许可、撤销后重建、断线、换维度或重生都会使旧确认失效。预览最多保留6000tick、256个玩家，不存盘；时钟倒退失效。
- 根存档升至24，独立ShearingPermits子树Version1。旧档缺字段为空许可，不从动物、观察、区域或围栏推导授权；新格式却缺字段时保留缺失并禁用。坏格式、未来版本、重复UUID或超限数据整段保全，不部分接受或自动清空。
- 许可变更只修改授权记录，不重置原库存、成员、工程或历史事件；没有在本步中增加动物捕获、出生继承或跨维度许可转移。

保护区在本步仅否决剪毛许可的预览/确认，不是原版动物行为的全局拦截。玩家、原版生物、发射器、其他模组及间接环境变化仍按其原行为运行。

## 为什么没有直接打开自动剪毛

已核查1.21.1剪毛实现：`Sheep.shear(SoundSource)`返回void，会置已剪状态并产生1–3个同色羊毛掉落实体；`readyForShearing`检查存活、未剪、成年。剪毛事件和剪刀耐久在玩家交互外层，单独调用shear不会替居民处理这些步骤。

后续必须一起接好：真实剪刀与原版耐久处理、移动目标寻路、逐羊短期占用、执行前实时许可和保护复验、只接收本次真正掉落、背包容量和残余掉落保全、独立用途货物及实际返仓。不能“调用原版剪毛后再造一份羊毛”，也不能靠附近物品前后差集猜归属；不能因背包满就把羊恢复未剪来补偿，否则可能重复产物。

本步没有增加Mixin掉落捕获，也未用项目实际字节码验证其调用owner/描述符。后续应先核对依赖，再实现窄作用域捕获本次真实ItemEntity；成功入包多少才从掉落扣多少，余量保留原实体。资格、工具与真实掉落事务未接齐前，不将许可表直接接入居民Goal。
