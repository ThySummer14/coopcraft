# 矿业生产、技术传播与劳动制度：研究及可实现设计 v0.1

> 日期：2026-11-09。状态：**研究提案，未实现矿井、机器或新制度**。
> 本文仅新增独立研究文档，不修改运行代码、存档、开发分支或已有研究PR。
> 目标：居民能够勘探并从地表开矿，即使附近没有天然洞穴；工具、物流、机器和知识改变实际生产；所有权、劳动控制与收益分配形成可观察的社会关系。

## 0. 先做什么

**先完成真实搬运，再做一个有限浅层矿井，之后才增加机器、发明与矿井制度。**

- 第一条可玩链：缺少某种原料 → 居民调查 → 试掘 → 开出可往返的阶梯巷道 → 真实挖矿 → 搬运入仓 → 用矿物继续生产。
- 天赋改变观察、判断和学习效率；不能凭空生成矿石，也不能代替工具、材料与已有知识。
- 技术决定能怎样生产；制度决定谁能使用设施、谁安排劳动、谁取得产品。两条轴分别演进。
- 玩家可以帮助、观察或离开。无需每天选矿工、排班或点击研发按钮。
- 本文的类型名、状态名和参数是讨论接口，不要求一次实现全部类和UI。

## 2. 真实物流是矿井的前置条件

### 2.1 一件物品只能处于一个权威位置

矿石流程采用：世界中的方块 → 采掘者携带的真实物品 → 运输者或运输容器 → 现场仓储/公仓 → 后续配方投入。

- 未真正抵达并交接，货物不能先出现在公仓、制作可用量或工资实物支付中。
- 在途货物必须可识别保管者、来源、目标、实际数量和当前状态。任务记录不能额外保存一份可消费物品副本。
- 模拟生产打开时，沿唯一库存适配在规定边界导入/导出；账本事件记录所有权/保管权变更，不能再次生成同数量批次。
- 满仓、路线阻塞、运输者离场或取消项目，不应删除货物或把它隔空送回。保留携带物，显式进入待交接、改目的地或可核查的回收状态。
- 若死亡使原版产生物品实体，恢复记录必须引用那份实际物品，不得同时恢复背包副本。首版若尚无可靠死亡交接，必须将其列为阻塞验收，不以“不丢物”声明遮盖未知结果。

### 2.2 开工门槛

首个矿井必须先证明：采掘者能带货回到同一真实仓库；仓库身份改变、取消、满载、同日重试和连续两次存读档都不会复制、丢失或隔空使用货物。未满足时只开发普通采集搬运，不扩大地下工作范围。

短缺发生时还应计算机会成本：开矿占用的人是否原本负责觅食、建筑或照料？工具和灯具是否挤占必需生产？首版用既有劳动预算和物资缺口表达，无需新增宏观经济总分。

## 3. 有天赋的居民怎样勘探

### 3.1 证据、判断与地下事实分离

原版矿物分布不是完整地质模型。初版只根据**实际可观察的信息**判断：已经看到的矿石、所在高度和群系、已知矿点、真实试掘样本以及有来源的别人报告。具体矿物生成规则应按1.21.1实际数据与整合包配置验证，不在本文硬编码“最佳Y值”。

建议一份报告保存：区域而非全部矿石坐标、目标资源、估计层位、已知证据、作者、观察时间、证据覆盖程度和判断等级。界面先用“线索不足/值得试掘/已有矿样”；没有做校准实验前，不给玩家看貌似精确的“83%成功率”。

**地质天赋**可以使相同证据下的地点排序更好、观察耗时更少、误判较少、学习更快。经验、教师与工具也能达到可用水平。天赋不是隐藏透视，不改变世界生成、不增加掉落，也不授予知识继承。

- 调查必须实际到场并消耗工时；远方报告保留来源与过期状态。
- 同一证据不反复随机重抽；保存观察结果及版本，新样本或新技术才允许合理更新。
- 不读取整个区块隐藏矿石作为“NPC直觉”。安全模块可在有界作业邻域读取危险状态，但不能把这些防护读取泄漏成找矿能力。
- 若未来采用自定义矿床和地表指示物，应单独评审世界生成、旧区块与数据包兼容，不悄悄修改既有地层。

### 3.2 谁提出项目

当真实生产链持续缺少资源，成年居民可提出调查。首版用“已启用矿业、允许开挖区、足够基本补给、存在可行任务”控制边界；在批准范围内由居民选择地点，无需玩家逐块标矿。

玩家或服务器管理员第一次划定有限开挖范围，以保护现有世界。之后可完全旁观。将来若扩展为聚落自治领地，领地范围与玩家保护范围必须有明确冲突规则，不能默认为NPC可挖全世界。

## 4. 没有洞穴也能形成矿井

### 4.1 项目状态

| 状态 | 可见行动 | 继续条件/退出原因 |
|---|---|---|
| 候选调查 | 居民到点观察并留下报告 | 无证据则换点或回到其他劳动 |
| 试掘 | 挖浅槽、试坑或短探巷 | 真实矿样支持继续；成本过高则封存报告 |
| 开拓 | 从地表逐段挖阶梯入口 | 工具、灯具、站位、退路及材料都有效 |
| 生产 | 掘进、采矿、搬运、补给 | 有实际需求与可工作的矿面 |
| 暂停 | 回撤或等待补给 | 展示缺镐、满仓、危险、路径阻塞等具体原因 |
| 停采/关闭 | 保存已建通道、残余货物与探查记录 | 耗尽、成本过高或撤销；不把地形重置为原状 |

恢复前逐项核验，不能把旧计划当作永久开挖许可。矿脉耗尽后允许开新工作面，但仍受原项目范围、预算和证据约束。

### 4.2 首版几何与执行

以下是**用于测试的保守候选上限**，不是已验证性能或最终平衡：每聚落一个矿业项目、一个活动工作面；地表下最多12格，开挖体限定在16×16水平范围；采用2格宽、有足够头部净空的阶梯路线和短水平支巷。路径、支护间距和照明规则由测试决定。

1. 在已知安全站位完成下一段计划，明确先拆哪一块、再放哪一块；不直接垂直挖脚下。
2. 只允许开挖配置白名单中的地形/矿石，使用真实手持工具计算可采性、掉落及耐久。
3. 同一次尝试只生成一份掉落计划，容量预演与最终入包使用同一份；重验目标、工具及项目版本，成功破坏后才提交产物、损耗和唯一完成事件。以有界、带版本的尝试记录或稳定随机策略阻止满包、取消和重试反复抽取随机掉落；目标失效时不得交付旧计划。
4. 为下一站位补齐通道、落脚与灯具；施工材料按实际放置扣除。
5. 工作面到安全出口的可达关系失效时停止新挖掘，优先可行回撤；不能凭缓存保证绝对安全。
6. 天然洞穴只是一种遇到的世界状态。首版不自动追入未调查洞穴，也不把它当作开矿前提。

原版石头不会普遍按地质力学坍塌。首版支护可作为拓展规则与可见建设成本，但应明确这是游戏约束；暂不增加真实塌方、气体、缺氧或随机伤亡系统。每一步破坏前检查有界邻域：存在流体接触、上方重力方块、未知深坑或无法判断的方块更新风险时，不执行该步。不能等拆掉最后一层石壁、已经淹没退路后才停工；保守检查仍不构成对任意模组更新的完整安全保证。

### 4.3 玩家建筑保护

原版旧存档不可靠地记录每块石头是否由玩家放置。不能承诺“自动识别并保留所有玩家建筑”。必须结合显式开挖区、禁挖区、方块白名单、容器/功能块拒绝以及当前布局检查。玩家修改、保护插件拒绝或其他聚落占用时，停工并给出原因；不得改换入口绕过保护拒绝。

## 5. 科技改变具体工序

| 改进 | 玩家能看见的变化 | 真实消耗与限制 |
|---|---|---|
| 镐与维修 | 更短开采时间、能开采新材料 | 工具等级、耐久、维修材料、工匠时间 |
| 支护与照明 | 可继续拓展的工作面 | 木材、灯具、施工及巡检 |
| 搬运器具 | 每趟能带更多，回仓次数变化 | 制造、通道宽度、维护 |
| 轨道与矿车 | 货物沿已建路线运输 | 铁、轨道、装卸、路径与车辆维护 |
| 提升设备 | 深井可运输的载荷变化 | 井架、绳索/部件、动力、操作员 |
| 排水设备 | 原本停工的积水区域重新可用 | 真实排水目标/容积规则、燃料和维修；暂不实现无代价消除水源 |
| 动力采掘 | 单个矿面开采能力提高 | 能源、零件、散热/维护等经验证必要的限制 |

生产能力应从真实作业时间和流量观察。可以用“采掘、运输、加工、排水中的限制环节”帮助解释停工，不能用最小产能公式直接生成库存。

例如镐快了一倍，搬运未变，可能只增加在途积料；有水泵但无燃料，湿区仍暂停。历史排水机案例支持把技术看成对瓶颈的解决，不支持统一时代倍率，见上表来源中的博物馆资料。

## 6. 发明、学会与广泛使用分别发生

### 6.1 问题驱动的创新循环

**实际问题 → 已有知识的组合 → 花材料试验 → 样机 → 真实试运行 → 可重复方法 → 教学与扩散。**

- 问题来自真实事件，如多次搬运耗时大、工具损坏或矿面因水停工。没有问题也可试验，但必须有活动、材料和机会成本。
- 创造性天赋使候选方案搜索更有效；普通工匠也能通过实践和交流改良。科研不能只有“等天才出生”一条路。
- 每项技术定义前置知识、设施、材料、可操作行为和验证条件。首版使用少量经设计的可发现方案，不宣称能够开放式发明任意机器。
- 失败留下试验记录并消耗约定成本，不能重复失败白拿熟练度；成功由真实样机结果判定，不能只因过了N天就解锁。
- 社会需求、交流与已有技术影响创新机会，但不把饥饿、压迫或某种社会制度硬编码成“创造力必然增加”。

### 6.2 知识属于个人及可访问记录

| 知识状态 | 可以做什么 | 仍然缺少什么 |
|---|---|---|
| 听说/见过 | 提出询问、识别设备用途 | 不能直接制造 |
| 会操作 | 使用和日常检查 | 未必能复制或修理 |
| 会制造 | 按已知方法造出设备 | 未必能改良或教好别人 |
| 熟练与可教授 | 可靠制造、指导学徒 | 教学仍占工时和实践资源 |

不要把所有新知识继续压进 `WorkType.CRAFT`。建议技术采用稳定数据ID，个人保存掌握范围、来源和练习记录；工种熟练度仍负责相应动作表现，两者互补。

初版优先复用现有 `KnowledgeSystem` 的有限指导机会与师生工时，不另造全村每tick传播。Minecraft接入需检查实际到场、双方资格、操作材料与完成事件。师徒、访问者和迁徙者传播时保留来源链；未接触者不自动收到全局解锁。

机器可以在发明者离开后继续存在；若无人会修理，它可能在损坏后停用。文书、图纸或学校应在以后成为真实保存/恢复知识的渠道，而非无条件永久科技仓库。新生儿不会直接继承父母完整技术。

## 7. 同一矿井中的不同劳动关系

### 7.1 把权利与物资保管分开

分析上至少需要识别：矿区开采权、设备所有、经营管理、实际使用、工作安排、产品收益、退出条件、规则来源和争议状态。初版共同矿井只实例化必要字段；其余在出现可玩的权利冲突时逐项增加。

矿工背着铁矿，不意味着矿工取得全部所有权；仓库装着机器零件，也不意味着仓库管理员拥有机器。账本须分别表示生产者、保管者、收益主体与变更依据，不再建一份“所有者虚拟物资”。

### 7.2 制度对照

| 关系组合 | 劳动怎样安排 | 产品怎样流转 | 要观察的后果 |
|---|---|---|---|
| 共同矿井 | 成员按共同规则投入劳动 | 真实入仓后按维护、公共需要和分配规则转出 | 协调成本、供给、照料、意见差异 |
| 领主劳役/贡纳 | 控制关键资源者要求家庭承担劳役或实物义务 | 对应劳动/产物实际转给权利主体 | 家庭余粮与工时、拒绝后果、执行成本、迁徙条件 |
| 雇佣经营 | 经营者发布条件，劳动者接受、拒绝或离职 | 产品归经营主体；工资另记实付/欠付及来源 | 实际工时、工资购买力、退出选择、库存与经营盈余 |
| 合作经营 | 成员共同控制设备并决定安排 | 按议定规则处理储备、扩建和成员分配 | 决策参与、履行情况、少数异议与可修订性 |

这些是机制组合，不是必须依次到达的年代。矿权、设备与经营权可以分属不同主体；同一居民可以兼有家庭生产、雇工与共同劳动。

**领主强制不能只是一条产量加成。** 若规则限制退出或强制服役，需要实际规则、执行者和成本，居民有具体经历及反应；没有执行能力时不能隔空让所有人服从。首个制度切片只做一种劳役/实物义务，不同时实现战争、监禁和完整国家机器。

**资本主义经营不能由“有工资”单独判定。** 需结合生产资料控制、工资依赖、面向交换的生产及盈余支配。市场和货币基础尚未可用时，只保留研究或用明确标注的实物雇佣试验，不伪造无限付款账户/收购者。

### 7.3 剩余、伤害与争议

- 展示真实工时、支付、维护投入和产品去向。矿石、粮食和工具按物种/单位分开计量；没有合法计价规则时不能将“10矿石减3粮食”算成利润。
- 会计利润、现金、未售库存和马克思理论中的剩余价值不同。若要分析后者，须另列劳动价值及必要劳动假设；首版不输出伪精确“剥削率”。
- 公共维护或照料扣除，与少数人控制劳动并占有剩余，要根据真实规则分别判断。职业名、国王称号和一次饥饿都不够。
- 强制劳动、危险和欠薪要表现受影响者的代价与主体性，不设计成无条件最优生产策略；也不预设所有冲突都只能失败或暴力解决。
- 申诉、协商、停工、辞工、迁徙和改革由具体经历、知情与组织条件形成。更换领袖姓名而产权/分配未变，不算制度变革。

## 8. 最小工程接法

### 8.1 边界而非一串必建类

| 能力边界 | 最小职责 | 首版应复用 |
|---|---|---|
| 勘探记录 | 区域、样本、来源与判断版本 | 已有居民身份、事件和存档 |
| 矿业项目 | 授权范围、计划、工作面、暂停原因 | 既有需求/任务调度，不重做全套居民AI |
| 单步开挖 | 权限、安全、工具、真实方块及产物提交 | 服务端动作规则；独立可测试执行函数 |
| 搬运交接 | 在途保管、到场验收、满仓/取消恢复 | 正在单独完善的统一真实物流能力 |
| 技术条目 | 前置、操作/制造能力、试验与教学 | `KnowledgeSystem`及制作/施工事件 |
| 资产规则 | 谁能使用/指挥/取得收益 | 后续经评审的通用权利与合同接口 |

保留一个行为协调入口，但不要把所有挖掘、采样、产权与机器事务都堆进 `VillagerWorkGoal`。纯Java核心用于决策和可重复实验，Minecraft服务端是方块变化、真实物品和实体到场的执行权威。

### 8.2 必守不变量

1. **范围**：动作在当前项目版本与授权体内；撤销后未完成动作失效，旧计划不能重新授权自己。
2. **真实劳动**：居民实际到场、有工时、使用正确工具；饥饿和休息仍能打断，不能困在无限往返任务中。
3. **唯一产物**：一次方块破坏只对应一次产物提交；预演和提交使用同一份掉落计划，重试不能重新开奖；一次交接只移动实际接收量；失败不产生经验或新批次。
4. **并发**：同一工作面/方块一次只有一个有效提交者；任务重试、重复包和重载不能重复完成。
5. **不强制加载**：仅处理已加载且实际活动的区块；卸载暂停，不按离线天数补矿或搬运。
6. **有限预算**：候选扫描、邻域检查、寻路和事件增长均有聚落及全服上限；优先复用既有开发探针。
7. **安全与权限重验**：缓存只优化规划，不替代最终站位、方块状态、工具和保护规则检查。
8. **保管与归属**：制度改变不能复制、清空或隔空转移在途物资；先更新权利依据，再依实际交接改变保管。

开发线 `SettlementHarvestCommit.java:13–24` 提供“完整容量计划 → 成功世界变化 → 背包提交”的同步模式，但明确不保证跨崩溃原子性；矿业增加工具损耗、多个方块或机器时必须重新界定事务，不直接扩大其保证。[固定提交源码](https://github.com/ThySummer14/coopcraft/blob/18f9ec2f3f01831b310f5cd9d9c548dfdc7834b4/src/main/java/com/thysummer/coopcraft/civilization/SettlementHarvestCommit.java#L13-L24)

开发线成员活动判定使用到聚落中心的64格三维距离，深井可能被误判离场。后续应引入有限登记工地的工作资格，不能把整个聚落半径无界放大，也不能顺便赋予矿工远程开会/监督权。[相关源码](https://github.com/ThySummer14/coopcraft/blob/18f9ec2f3f01831b310f5cd9d9c548dfdc7834b4/src/main/java/com/thysummer/coopcraft/civilization/SettlementMembership.java#L15-L31)

新增持久状态使用稳定ID和显式格式版本，旧存档默认没有矿井/报告/新技术。不要仅因加载旧居民就替其补造发现或产权。至少连续两次保存/重载检查同一项目、货物与知识来源。

### 8.3 最小玩家信息

继续使用居民窗口、矿口方块和既有事件页：当前工作、目标、带着什么、为何停止、下一次可行行动。普通玩家不需要看全部概率、阶级指标或配方图。研究用统计通过开发命令/导出显示，不每tick向所有客户端同步整个矿山账本。

## 9. 分期与进入门槛

| 切片 | 最小交付 | 先决条件 | 暂不做 |
|---|---|---|---|
| M0 真实物流 | 普通资源携带回仓、到场交接、取消/满仓/重载恢复 | 现有真实采集与唯一库存 | 地下扩张、远程建材可用量 |
| M1 浅层开矿 | 有界踏勘、试掘、阶梯入口、一个矿面、真实矿石回仓 | M0通过；工具等级与耐久、保护范围、可退回路线 | 深井、电力、塌方、完整地质世界生成 |
| M2 矿业生产链 | 采掘/运输分工、燃料、冶炼、修理和新工具 | M1可玩；加工守恒 | 统一时代产量倍率 |
| M3 一项可传播发明 | 一种搬运设备的试验、样机、再制造、教学与维修 | M2有可量化瓶颈 | 任意机器自动发明、全局科技解锁 |
| M4 一项矿井制度 | 同矿井条件下，一种劳役或雇佣规则及真实转移/退出 | 工时、权利和支付基础可用；相关通用规格已评审 | 同时实现全部社会形态、战争和金融体系 |

研究可继续准备后续切片；开发每次只交付一条闭环。M4不要求先完成蒸汽技术，M3也不要求先出现资本制度。顺序表示工程依赖，不表示历史必经阶段。

## 10. 验收与对照实验

### 10.1 可见的成功与可接受的失败

**15分钟观察场景目标，待实测调整**：玩家进入已启用的聚落，发现居民调查和试掘；缺灯具时居民能说明原因；补充真实灯具后继续；最终矿石由携带者回仓。无矿样时应解释暂停/换点，不为了“剧情成功”生成矿石。玩家离开后不需要远程点击，但卸载区域不会继续产出。

### 10.2 实现PR必须给出的测试

| 场景 | 必须满足 |
|---|---|
| 完整地表、没有洞穴 | 能按计划开出可往返入口，不依赖现成空腔 |
| 贫矿/无矿 | 不生成替代矿石；有停止原因与保留的调查记录 |
| 重复同证据调查 | 不靠重进/重载反复抽出“成功”，新证据才改变判断 |
| 错误镐、镐损坏、满背包 | 无非法掉落、免费耐久或破坏后丢弃整批产物 |
| 附魔镐、多种随机掉落、容量不足再试 | 容量计划与实际产物一致，时运等随机结果不因重试反复抽取 |
| 玩家取消/缩小开挖区 | 尚未完成动作停止，旧任务不能挖出范围 |
| 玩家改地形、插入容器、保护拒绝 | 复核失败即停，不绕过权限、不覆盖建筑 |
| 水/熔岩或砾石隔着最后一层石壁 | 破坏前检查并保留隔离壁，不能先触发危险再宣布停工 |
| 未知洞穴或无法判断的方块更新 | 按首版边界停工并说明，不声称完成全面风险模拟 |
| 两个工人选择同一矿块 | 只有一次有效破坏、产物、工具损耗与经验 |
| 在途货物、满仓、仓库拆改、项目取消 | 产物在唯一真实位置；不可提前用于配方或重复恢复 |
| 携带者死亡、掉落实体被玩家拾取/销毁、交接途中重载 | 不依据旧任务重造物品；记录可核查的实际转移/损失原因，不能同时恢复背包与掉落实体 |
| 饥饿、跨日、工作者离场 | 正常中断与再规划，不重复完成、不破坏需求优先级 |
| 未加载目标、卸载后再加载 | 不触发隐式区块加载，不补算离线产量 |
| 两次保存重载、重复网络请求 | 项目、货物与知识身份不变；每个完成事件只结算一次 |
| 超过原64格三维活动范围 | 资格规则明确，登记矿工不意外失去工作；仍不能远程参会 |
| 关闭矿业/移除项目 | 停止新动作，保留已改变地形与真实物资，说明恢复方式 |

### 10.3 不预定赢家的比较

- **勘探**：同一组地图、种子、材料和工时预算，比较随机选点、普通学习者、熟练/有天赋居民；统计实际找到的矿、废石、路程和失败投入。单次好运不能证明天赋有效。
- **物流**：只换镐、只改搬运、两者都改，与基线比较；预期瓶颈变化必须能从实际时间/积料解释。若只换镐也无条件翻倍入仓，检查是否跳过运输。
- **知识**：同样人口比较孤立发明者、实际教学、只有成品展示；检查可制造者数量、总劳动与材料消耗、持有者离开后的恢复。不得预设人口数自动决定科技。
- **制度**：同一矿体、工具、技能与补给，分别使用共同安排和一种新劳动规则；记录各人实际工作、所得、拒绝/退出、监督成本。不要直接给某制度额外效率倍率来保证结论。

### 10.4 工程与性能验证

实现验收以 `AGENTS.md` 为工程参考，但执行必须遵守当前任务允许的测试范围。当前不启动Minecraft、GameTest或会运行游戏的CI；以下列出未来获得测试许可后的验收要求，不表示本轮已执行。分别报告已通过、失败和未执行的项目，不能把纯Java模型通过写成真实寻路/视觉通过。

采用同世界、同人数、同视距，比较矿业开/关及1/多个聚落，测服务端MSPT、扫描次数、路径请求、网络包与客户端帧时间。本文未测性能，不宣称达标；任何数值阈值在测量后另行冻结。首次实现应给上限触发时的降级行为，而不是只测一座平地矿井。

## 11. 尚待验证的问题

1. 不增加自定义地质生成时，现有世界证据能否让勘探比随机试掘明显更有趣？若效果不足，先缩小为露头追踪/样本判断，不用隐藏全图扫描弥补。
2. 村民原版导航能否稳定往返候选阶梯断面？实机失败应先调整几何和任务切换，不能加传送来伪装搬运。
3. 当前物流如何处理死亡、物品被玩家拿走和模组回调？只有已测的边界才能写入保证。
4. 第一种搬运设备是否真正解除已观测瓶颈？若只是面板换名，应延后发明系统。
5. 缺少完整市场时，先选劳役还是实物雇佣更可验收？留给M4范围评审，不在浅矿实现中提前承诺。

**收束标准**：M1需求足以开工后，后续史料留在研究；只有发现会改变权限、守恒、玩法或验收的新证据才回改M1。研究深度不应让开发无限等待。
