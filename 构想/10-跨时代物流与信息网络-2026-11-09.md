# 跨时代物流与信息网络：从肩挑背负到协同调度

日期：2026-11-09。状态：研究规格 v0.1，待审阅；没有实现下述新系统。

## 0. 结论与范围

**文明物流的进步，是把“搬得动、走得通、接得住、消息可信、有人维护”逐项解决，而不是把村民换成更快的载具。**

- 货物网络与信息网络分开：驿骑能更快送来缺粮消息，不能让矿石同步到仓；信息时代减少空跑、等待与错配，不改变货物的物理位置。
- 运输方式并存：肩挑服务矿井最后一段，驮畜跨窄山路，车队走平路，船运连接河港，铁路承担稳定干线，汽车补齐支线。水运可以很早出现，不须先经历马车时代。
- 发展取决于本地地形、流量、材料、能源、技能及组织能力。没有河流的矿村、河口港城、高山聚落会走不同分支；断供与失修也会使能力退化。
- 本轮优先把真实装卸与在途归属做可靠，再做一条能观察的短途驮运。轮船、火车、汽车和信息调度是后续研究入口，不加入当前开发的必做清单。

本文补充[矿业研究 PR #42](https://github.com/ThySummer14/coopcraft/pull/42)，沿用[研究文库 PR #24](https://github.com/ThySummer14/coopcraft/pull/24)的非线性发展原则，与[S4 商业规格 PR #40](https://github.com/ThySummer14/coopcraft/pull/40)共享运输概念，不另造市场、货币或产权账本。[产品纲领 PR #41](https://github.com/ThySummer14/coopcraft/pull/41)约束每个切片只交付一种可玩循环。

## 4. 地理与路线成本

### 4.1 两张图和一个现实世界

- 货物图：节点是矿口、仓库、农庄、码头、车站等实际交接处；有向边记录允许的方式、已知路段、容量、装卸约束和最近核验时间。
- 信息图：节点是有观测能力的人/站点；边记录传递方式、延迟、容量、可靠性及允许接收者。消息可以沿旅人随身携带，也可沿专用信号线走。
- 两图只表达计划和已知状态。Minecraft中实际可达性、物品及实体仍是执行权威；不能把图上的连线当成已经修成的道路。

山地的窄路径不等于轮车道路；水路上下行可以成本不同；渡口等待、港口排队和装卸要计入总行程。水深/天气/季节只在对应世界观测或显式实验模型实现后生效，原版没有的潮汐、河流流量不得默默假装存在。

### 4.2 单位和选择规则

先用游戏单位，不冒称真实公斤或小时。`cargoUnit` 是数据配置定义的运力单位，`ItemStack`仍保留原有件数及components。M0继续以容器实际容量为准，不突然压缩村民原有背包；质量/体积模型须另做兼容开关。若启用负载规则，应同时约束体积、载重与原版槽位，而不能让64块石头和64根羽毛永远同重。

对于候选路线 r，分别报告：

`T(r)=装货 + 排队 + 行驶 + 转运 + 卸货 + 等待补给/修理`。

成本向量为 `{居民劳动ticks, 饲料/食物件数, 燃料件数, 工具/载具磨损, 设施维护材料, 费用, 预计损失, 交付时间}`。未建立市场价格前不把这些异质单位直接相加成“金币成本”；先排除不满足期限、权限与资源预算的方案，再按需求规则选取。生存急件偏重按时到达，建筑散货偏重劳动占用和可持续成本；同值按稳定ID排序。

稳定流量才值得高固定成本设施。独立实验可比较 `F铁路 + q×c铁路` 与 `F替代 + q×c替代`，但只有四项采用同一实验成本单位时才能算交点。运行时仍消耗真实材料、能源及工时，不能直接扣一个虚构总分。

周期运力受装卸能力、最窄路段、可用运载者及终端接收能力共同限制。返空、必要返程口粮与下次补给必须入预算；不让满载运力指标掩盖大量空跑。

## 5. 工程契约：货单不是第二份货物

以下是候选接口，不是已新增的Java类。与PR #40已有`Shipment`、`PropertyRight`和`CommerceRoute`命名协调，开发时沿用一套模型。

| 对象 | 最小字段 | 不变量 |
| --- | --- | --- |
| `LogisticsNode` | id、dimension、位置、kind、实际容器绑定、开放规则、装卸能力 | 位置不充当稳定身份；同坐标替箱会使旧票失效 |
| `RouteSegment` | id、from、to、allowedModes、geometryRef、condition、checkedAt、revision | 有方向；UNKNOWN不等于可通行；几何缓存有加载边界 |
| `Carrier` | id、kind、entityId、capacity、energyOrFeed、maintenance、availability | 实体存活且符合当前资格；不能重复派车；载具库存只有一个权威 |
| `Shipment` | id、requestId、ownerRef、custodianRef、routeRevision、legIndex、cargoRef、requested/loaded/delivered/remaining、status | 数量为执行结果/预期的账面索引，不是可另行花费的库存；cargoRef指向唯一实物权威 |
| `CargoAuthority` | PHYSICAL_CONTAINER或SIMULATION_BATCHES，加对应唯一引用 | 两种模式互斥；不能只凭金额或货单生成ItemStack |
| `Reservation` | id、shipmentId、resourceOrCapacityRef、quantity、expiry、revision | 只是排他承诺，不增减总量；装载和卸载时重新检查，失败释放/缩减 |
| `TransportObservation` | id、shipmentId、observedAt、observedPlace、observer、state、sourceEvent、channel、receivedAt | 观测时间不因转发刷新；无观测标未知；广播受渠道与接收权约束 |
| `AccessAgreement` | route/node、持有/使用/运营/收益主体、劳动与供给义务、有效范围、撤销版本 | 与实物保管分开；职业、科技和仓库标签不自动授予权利 |

物理货物可先以不可变物品指纹及容器/槽位版本建立短期预留，出发时重新读栈；若槽位被玩家或漏斗改动，不使用旧快照补货。长期货单记录来源与数量，不序列化一份可恢复发放的物品副本。通用货箱是后续明确授权的单一容器，不同时把箱内和外层货箱都算入总量。

### 5.1 状态机与部分交付

`PLANNED → RESERVED → LOADING → IN_TRANSIT → WAITING_UNLOAD → DELIVERED`。

- 出发前取消：解除预留，无实物变化；`CANCELLED`只用于未装货的请求或已完成实物处置的余量。
- 装载：到达装货位后重新核验成员、权限、容器绑定、路线/载具、容量和实际原栈，仅对真实移走量记录`LOADED`。
- 中断：`PAUSED_UNLOADED`、`WAITING_SUPPLY`、`WAITING_ACCESS`、`ROUTE_BLOCKED`保留当前保管者；不能把“没加载到”认定死亡/损毁。
- 到达：单有ETA、靠近中心或寻路返回成功不能交付；必须满足当前实际站位和接收权限。
- 部分卸货：收到多少只减多少，剩余保留运载者；`WAITING_UNLOAD`仍为在途。已完成部分不得随取消而退回复制。
- 已装货后取消/撤权：按约定等待、返运或转到有权接收的安全点；没有合法可达接收者就继续保管，不能瞬间回原仓或销毁。
- 死亡/事故：从已观察到的真实库存移交遗物/事故保管；重复事件不补发。当前死亡保全只覆盖已有材料与事件路径，车船要单独实现。
- 被劫是保管转移，腐败/燃烧才是消耗或销毁。未知去向用`UNACCOUNTED`并保留证据，不把信息丢失等同货物消失。

`shipmentId + legIndex + transferSequence`是候选幂等键。同一服务端线程同步提交源容器扣减、目的容器增加与结果事件；仅承诺标准、非重入且互不重叠容器中的单次提交。共享槽位/双箱别名必须识别或拒绝。未知模组容器若无法保证合同，停在明确的不支持状态。

正常保存/重载要防止重复认领；独立实体、区块和SavedData文件不提供进程崩溃原子性。当前阶段不引入“看不见就重发”的恢复。未来若要跨文件崩溃恢复，应先独立设计持久提交日志与对账，不能靠货单快照重建物品。

### 5.2 守恒与双系统隔离

对每种物品及完整components分类，在无转换的小实验中：

`期初 + 有来源生产/导入 = 当前仓储 + 运载容器 + 合法遗物/事故容器 + 已记录消费/毁损/导出`。

预留、货单、交付累计数和到货预测不加入右侧存量。加工实验按配方追踪输入输出，不能跨不同物品直接用件数总和证明守恒。

独立核心实验只用`ResourceBatch`。Minecraft实体运输只用真实容器。跨模式交接必须复用显式、版本化的库存适配边界：同一份货物不得既留在驴背包又记为可支出的在途批次。现有`TradeSystem.exchangeOneForOne`保持旧实验语义；启用新运输合同的交易必须转交新执行路径并关闭该笔即时交换，不能先成交搬走一次、抵达再搬一次。

### 5.3 时间、加载与规模

- 第一版实体物流只在已加载且满足entity-ticking的边界内工作，沿用现有活动范围；跨维度、离线追赶、强制加载区块均不做。
- 卸载暂停在途进展、站点操作和相关截止计时；重载重新绑定实际实体/容器、复核位置和权限，再继续。不可用现实经过的时间直接算到货。
- 实体动作统一使用服务端游戏ticks；独立模拟的“小时/日”只在实验适配器换算，不同时让移动Goal和每日社会小时重复扣劳动。开发任务先选定一个工时权威。
- 只在相关方块/绑定/权限变化后让缓存失效；增量处理候选路线，有每tick预算、轮转公平和退避。取消/中断释放瞬时票据，不能无限卡住运载者。
- 初始实验上限建议为每聚落4个节点、8条有向边、16个活跃货单、每轮最多处理4单、每货单最多2条候选路径。这些为配置试验值，不是已测性能保证。
- 长途抽象运输是独立后续项目。只有单一所有者和往返交接均通过幂等/重载测试后才允许离开实体模拟，禁止先卸载实体再在目的地复制生成。

## 6. 驿站与信息时代的签名玩法

### 6.1 驿站不等于免费物流塔

河谷营地粮食吃紧，信使携带一条有来源的请求到矿村。中间站若有已休息的驿畜与接替者，可交换消息携带者，旧畜仍留站休息，食物从该站真实供给中消耗。若站点缺补给，可以继续较慢行程或等待，不能把“通过驿站”变为无限恢复。

矿村收到的是发报时的缺粮量。重复转发只更新得知时间，不刷新观测时间；延迟消息可能已过期。粮食是否真的能发运还要检查矿村储备、权利、运力与河道。急报和大宗货物可以走不同路线。

首个驿站实验只做消息交接与有限补给，不做全国邮政、随机劫匪或复杂税制。人物从信使活动中获得实际经验，教学占用师徒时间；建站本身不让全部居民瞬间掌握路线。

### 6.2 信息升级改变决策质量

最早的当面告知/随商队带话、专职驿递、固定站点信号与后期协同系统逐渐叠加。升级减少的是信息延迟、漏报与重复派送，可加入到货预约、同向拼载和返程配货。

只允许使用各节点已经报告的数据；系统不能直接读取没建立联系的聚落仓库。每个界面显示“12分钟前于河港装船，预计3分钟后到达”，而非“全世界货物的真实坐标”。信号中断后保留最后观测及时间，不把未知显示成空仓，也不把断线自动宣告货物丢失。

铁路先实现区段独占/会车等待及失去信号时停车，避免把“红石连接成功”当作穿过另一列车的许可。后期调度只在有凭据的空闲区段和接收预约内发车，安全约束优先于吞吐。

## 7. 维护、制度与社会差异

道路、马匹、站点、码头、车辆及通信设施的“谁拥有、谁使用、谁管理、谁出资、谁受益”分别记录。可以共同出工修桥、由商队付费养路、由公共仓供养驿站，也可以出现收费、特许经营、劳役或雇佣。技术不直接指定任何一种制度。

第一版只在已有共同聚落中实现公共需求与劳动分配，制度扩展沿PR #39/#40的产权、义务与财政模型，避免给运输服务另建一套经济系统。

| 机制 | 可观察后果 | 不允许的捷径 |
| --- | --- | --- |
| 维护义务 | 修路耗掉实际材料和劳动，维护不足使可靠性下降 | 每日固定扣币却不发生任何实际维修 |
| 使用/通行权 | 撤权后停在安全节点，保管责任不凭空消失 | “科技已解锁”绕过私人货物或禁入区域 |
| 费用与公共供给 | 有货币时调用同一MoneyLedger；无货币时按明确协议转移实物或劳动 | 运费凭空生成金钱，过桥自动把费用烧掉 |
| 运输劳动 | 搬运、赶牲畜、装卸、修理、记录占用有限时间；保障照料与休息 | 货物运输同时全额从事另一份生产 |
| 路线控制 | 收费/排队规则影响谁能取得物资、谁承担维护 | 职业“商人”自动获得所有货物的收益权 |
| 中断与替代 | 铁路缺燃料后部分货物改走旧车路，贸易可能缩减 | 自动回到“更低文明时代”并抹掉已学知识 |

应对比制度如何实际影响准时供给、居民负担、费用归属与故障恢复，不根据名称预设优劣。诊断“运输枢纽”需要持续实际流量与转运活动，不能只由车站建筑存在判定。

## 8. 分片顺序与进入门槛

| 切片 | 只做这一条循环 | 完成门槛 | 暂缓内容 |
| --- | --- | --- | --- |
| L0：材料返仓基线 | 标记采集 → 实体背包 → 安全到仓 → 按容量卸下 | 已有开发线功能；源码和无游戏单测能核对，但实际Goal/死亡事件表现待用户游戏验收 | 不把已有1062项整体测试数量当成此规格新功能通过 |
| L1：一次可追溯的近距装卸 | 已授权源仓 → 单居民 → 已授权目的仓，限一个现有材料种类 | 无远程取料；重复/部分/撤权/卸载/重载均守恒；界面能说明阻塞 | 不同时重写食物、施工、制作全部旧路径 |
| L2：一种实际驮运 | 1名照料者+1头获授权驮畜，矿口或源仓 ↔ 公仓 | 唯一运载容器、到场装卸、动物死亡/卸载与补给不足可恢复；窄路/门测试明确 | 不做任意牲畜、自动繁殖、载具经济 |
| L3A：一次消息中继 | 两聚落通过一站交换带时间的缺料报告 | 去重、时效、补给、观测与收报时间不同；信息到达不移动货物 | 不做全知市场和无线全图导航 |
| L3B：一种转运 | 徒步/驮运 → 固定渡船或短轨矿车 → 目的仓 | 换装只转移一次、站满会等待、排队不饥饿、两端身份可核验 | 船和矿车二选一先做，不并行造整套交通工具 |
| L4：基础设施投资 | 在一个已存在瓶颈上修路/建码头/铺短轨 | 前后对照中看到真实吞吐与劳动占用变化；材料、维护和机会成本有来源 | 不设自动全国修路AI |
| L5：动力干线与支线 | 燃料链完整后添加一种动力运输 | 燃料断供、区段冲突/道路阻塞、终端瓶颈和返空可解释 | 火车、汽车、动力船不同时承诺 |
| L6：信息协同 | 已有物流上加入预约与返程配货 | 同等车辆/速度/容量下等待或空载降低；断讯退回保守运行 | 不以增加车辆速度伪装信息改善 |

L3A可先于L2或L3B开展；早期水运也可先于轮车。下一切片选择由当前可观察瓶颈和开发成本决定，不以历史年代强制排序。每个切片单独开开发PR、默认关闭未成熟能力、单独注明验证层级。

### L1可交付任务卡

1. 单一货种先选普通圆石；选两个已存在且明确绑定/授权的容器，不自动搬玩家私箱。开发配置限定已加载范围和一单一搬运者。
2. 抽出源/目标实际容器近距交接服务，复用当前成员、仓库身份、标准容器与到场检查模式，不直接修改旧短期票据为持久对象。
3. 加入只包含引用与计数的货单状态，界面先用“待装、运输中、等待卸货、暂停与原因”；ETA在没有路径证据时标未知。
4. 接入运输Goal：实际到源仓装货，沿可用路线移动，到目的仓按接收量卸货。紧急生存/危险可中断，不能以运输优先级压住避险。
5. 保存实际在途库存及货单引用；正常重载重核，不从货单补货。补上重复事件、竞争与部分转移服务测试。
6. 只有该循环通过静态/纯Java服务测试后才申请后续统一游戏验收；本研究任务不启动客户端、服务端或GameTest。

## 9. 可复现实验与验收

以下是未来实验规范，不是本次已运行结果。实验参数保存在独立fixture，固定种子仅用于确有随机性的部分；同一扰动只发生一次，禁止重试重抽直到成功。

### 9.1 四个对照

| 实验 | 控制变量与干预 | 需要记录 | 判定 |
| --- | --- | --- | --- |
| E1 山路与平原 | 相同货量/出入口；A为轮车不通的窄阶路，B为满足轮车条件的连续平路；比较徒步、驮载、车 | 实际交付、劳动、补给、失败原因 | 不应有一种方式在所有地形无代价占优；不能把路径失败伪造为慢速到达 |

### 9.2 最低测试矩阵

| 编号 | 场景 | 必须成立 |
| --- | --- | --- |
| T01 | 预留成功但未装货，随后取消 | 所有实际库存不变，预留释放 |
| T02 | 两搬运者争同一批货 | 总装载不超过可用原栈，无双重认领 |

| T04 | 装卸时同坐标换箱、双箱结构变化、成员重新绑定 | 旧票失效，无不明扣货 |
| T05 | 目的仓只剩部分容量 | delivered只计实际接收，余货仍在运载者 |
| T06 | 同一到达回调重复两次 | 第二次无重复转移/技能/付款事件 |
| T07 | 行进中区块卸载和再次加载 | 暂停且不追赶，到场检查仍执行 |

| T09 | 载具/居民实际死亡、同一死亡重复回调 | 只从真实库存移交一次，不在实体和遗物两处同时存在 |
| T10 | 实体未被找到，但没有死亡证据 | 标未知/等待，不触发赔付、补发或销毁 |
| T11 | 出发后权限撤回、目的地拆除 | 在合法位置等待/返运，未交付余量有保管者 |
| T12 | 通道堵塞、过陡/过窄、渡口被拆 | 有界退避和可读原因，不透墙交付 |
| T13 | 混装components不同的相同物品 | 保留原栈差异，不能错误合并或洗掉属性 |
| T14 | 食物/燃料预算不足、动物需要休息 | 发运前拒绝或途中明确等待，无免费补给 |
| T15 | 中转重复、部分卸后转乘、取消余量 | 每一腿沿用同一货物来源，不二次生成 |
| T16 | 消息重复、晚到、乱序或转发 | 去重，保持观测时点，不用旧报覆盖新报 |
| T17 | 新信息与实际库存不一致 | 信息只影响计划，装货以当前权威库存为准 |
| T18 | 一条铁路区段两车竞争、信号中断 | 不同时授权冲突占用；未知时等待 |
| T19 | 同一物资经过模拟/物理显式边界 | 任何时点只有一个可支出权威；即时TradeSystem不再重复交换 |
| T20 | 刚完成部分交付后返回原仓 | 只返当前余量，不按原始requested补回 |
| T21 | 一条高优先级线路持续有需求 | 低优先级货单有明确公平/延期机制，无无限饥饿 |
| T22 | 配置关闭、旧存档、未知版本、损坏引用 | 不迁移未授权库存；未知数据保留并停止写入，错误可诊断 |
